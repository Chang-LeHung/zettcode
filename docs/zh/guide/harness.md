# JIT harness

开启 just-in-time harness 后，模型可以自己写一个小的 Python 工具，加载并在同一轮里调用，而不必只用随程序附带的那些工具。
它默认关闭，需要你主动打开。

## 发生了什么

1. 模型用 `repo_create` 工具创建一个仓库，再用文件工具往里写一个工具。工具就是普通 Python，放在
   `~/.zettcode/harness/<工作区>/<会话 id>/` 下。
2. 它用 `repo_load` 加载这个仓库。代码在自己的**子进程**里导入，所以崩溃或卡死不会影响你的窗口。
3. 它像调用其他工具一样调用它。每一步都是对话里可以展开查看的行。

一个会话只保留一个仓库。已经有的话，模型会被告知复用它，而不是再建一个。

## 怎么打开

| 方式 | 效果 |
| --- | --- |
| `/harness gen [描述]` | 为本次运行打开 harness，并让模型以这段对话中的一轮，为这个工作区造一个小工具并汇报。 |
| `[harness] jit = true` | 让每次运行启动时就是打开的。 |
| `/plugins` | 在下次启动时打开或关闭它。 |
| `/harness reset` | 为本次运行关掉它，之后的请求就没有它的工具了。不会删除任何东西：本会话写的工具留在 harness 目录里，命令会列出路径。 |

```toml
# ~/.zettcode/config.toml
[harness]
jit = true
```

```text
/harness gen 列出这个仓库里的 TODO 注释，按文件分组
```

`gen` 后面写的是你自己对要什么的描述。模型会被告知把它当作优先于命令自带建议的要求：里面写"不要动 X"就会遵守，报告里也会说明是否满足。
超过 4000 个字符的描述会被截断，消息里会标出从哪里截断。`gen` 会让这个窗口里的所有会话都打开 harness。请求进行中不接受这条命令。

`gen` 的提示要求造一个小而具体的工具：一两个工具，够用就用标准库，并且在说它能用之前，至少在你的工作区上跑一次。
提示还告诉模型把写入限制在 harness 目录里，不要改你项目里的文件。这是对模型的指示，不是沙箱。

## `/harness` 面板

`/harness` 打开一个只读的全屏表格，列出 `~/.zettcode/harness` 下所有仓库，包括其他工作区的会话。`Tab` 在 **Harnesses**、**Tools**、
**Files** 之间切换。它只读声明文件、不导入任何代码，所以显示的是仓库声称定义了什么，而不是代码实际做了什么。

在某一行上按 `Enter` 会把那个 harness 借给当前对话：之后 `gen` 和 `repo_create` 会写进对方会话的目录，
直到窗口关闭，或者你选回自己会话的那一行。

## 代码在哪里运行

子进程是模型写的代码和你的会话之间的边界。进程里的代码受到什么限制，取决于你的 shell 级别：

| shell 级别 | harness 代码运行时 |
| --- | --- |
| `full` | 拥有你自己的权限。 |
| `safe` 或 `ask` | 在 `safe` 使用的边界里运行。两者共用同一个边界，所以在它们之间切换不花任何代价。 |
| `deny` | 仍然运行模型写的 Python，在 `safe` 边界里，因为它不是 shell 命令。 |

在没有沙箱的机器上（Windows，或没有可用 `bwrap` 的 Linux），harness 会在每个会话里说一次，模型写的代码不会在你不知情的情况下失去边界。

把级别切到或切出 `full` 会改变边界：子进程被关掉，下一次请求重新起一个，模型自己写的工具要再跑一次 `repo_load` 才会回来。

## MANIFEST 与 BAN_TOOLS

仓库要在 `__init__.py` 旁边放一个 `MANIFEST` 来声明自己：name、version、description，以及可选的、它声明的 `tools`。
没有 `MANIFEST` 的仓库不能加载。把工具写进 `MANIFEST` 的 `tools`，`repo_load` 才会检查模型的成果。

同一目录下的 `BAN_TOOLS` 文件列出这个仓库不允许定义的工具名。

## 它做不到什么

- **在 `full` 下它不是沙箱。** 那一级别里，代码拥有你的权限，模型运行的命令也一样。
- **它不会让 `/harness gen` 自动变得安全。** 把写入限制在 harness 目录里，是要求模型自己做到的。
- **`reset` 不会删除**会话写下的东西，只是让之后的请求没有 harness 的工具。
- **它碰不到别的会话的工具**，除非你在面板里借用那个会话的 harness。
- **会话被另一个 ZettCode 进程持有时**，`gen` 会回答 `Nothing was changed`，因为一轮开不起来；`reset` 仍然会关掉本窗口的开关，
  对那边没有任何影响。
