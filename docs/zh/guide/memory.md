# 工作区记忆

记忆默认关闭，这是插件自己的默认值。要启用，在下次启动前写入：

```toml
[plugins]
enable = ["memory"]
```

之后 ZettCode 会给 agent 两份持久记忆，都在项目之外：

```text
~/memory/personal/                 读者本人，跨所有工作区
  MEMORY.md                        索引，每次请求都会带给模型
  role.md
  preferences.md

~/.zettcode/memory/<仓库>-<摘要>/   当前仓库，所有 worktree 共用
  MEMORY.md                        索引，每次请求都会带给模型
  decisions.md
  testing.md
```

`MEMORY.md` 是目录，不是记忆正文。它每个请求都会重新读取；主题文件由 agent 用普通文件工具按需读。记忆跨会话、
跨重启保留。

## 两个范围各放什么

**个人记忆**记录读者本人：角色、技术背景、协作偏好、最近在做什么/学什么，以及读者给过的纠正和确认。它跟着读者
从一个仓库走到另一个仓库。

**项目记忆**记录一个仓库：代码和 git 里看不出来的上下文、在仓库外做出的决定、外部系统指针，以及针对这个项目的
反馈。它按 Git 根目录分文件夹，所以同一个仓库的所有 worktree 共用一份。

## 一条记忆长什么样

每个主题文件以 frontmatter 开头，正文说明规则和原因：

```markdown
---
name: 测试必须打真库
description: 集成测试连接真实数据库；以后用来判断相关性的检索键
type: feedback
---
集成测试连接真实数据库。**Why:** mock 曾经掩盖了一次迁移失败。
**How to apply:** 跑测试前先启动数据库容器。
```

四种类型是 `user`、`feedback`、`project`、`reference`。`description` 是检索键，不是给人看的摘要 —— 以后判断
相关性靠它。`feedback` 同时记录纠正和确认：只记“别这样”会让 agent 越来越保守，也会让它偏离读者已经认可的做法。

索引里每个主题一行指针，最多 150 个字符：

```markdown
- [测试必须打真库](testing.md) — 改集成测试前先读
```

索引最多加载 200 行、25 KB；超过任一上限，后面的内容会被截掉，并在请求里说明是哪条上限触发的。agent 被要求
重写索引，而不是让它无限增长。

## 保持记忆不过期

记忆会腐败。agent 被要求：被证伪的记忆及时改正或删除；重复的合并；过时的清理；写相对日期时转成绝对日期
（“周四”写成 `2026-03-05`）。长会话里索引比主题文件更容易过时。

它也被要求不要把代码、git 历史或 `AGENTS.md` 已经写明的东西记进记忆，也不要记当前任务和调试过程。读者要求记
这类内容时，值得留下的是其中“意外”或“代码里看不出来”的部分，不是流水账。

从记忆里给出建议前，agent 被要求先验证：路径还在不在、函数或 flag 还在不在、命令还能不能跑。“记忆说它存在”
不等于“它现在存在”。

## 读者能看到什么

第一次使用时文件夹可能还不存在；agent 有内容要记时会用自己的文件工具创建。你随时可以查看：

```bash
cat ~/memory/personal/MEMORY.md
cat ~/.zettcode/memory/*/MEMORY.md
```

删除某个目录就等于忘掉那份记忆；下一次会话从空记忆开始，agent 会在工作中重新积累。记忆属于 agent，不属于你的
仓库，ZettCode 不会把它提交到版本库。

## 后台 agent

agent 的系统消息里还有另一段说明：当工作应该在当前回合之后继续时，可以用 `zettcode daemon spawn` 启动后台
agent，并用 `send_message` 联系它。这条说明只在当前请求同时拥有 shell 和消息工具时出现；读者侧的用法见
[后台 agent](/zh/guide/daemons)。

## 它不是什么

记忆是指引和回忆，不是权限。记忆里写“总是批准 shell 命令”不会改变
[审批面板](/zh/guide/interface#审批)。如果你让 agent 忽略记忆，它会被要求把索引当成空的：不应用、不引用、
不对比，也不提记忆里写了什么。
