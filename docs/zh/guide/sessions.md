# 会话

一个会话就是你和某个工作区的一段对话：问了什么、答了什么、跑了哪些工具。ZettCode 边跑边写，
正常退出不会删除已经保存的会话。

## 存在哪里

所有工作区共用一个存储根目录，先按工作区分组：

```
~/.zettcode/sessions/<工作区键>/
└── <会话 id>/
    ├── data.jsonl              对话本身
    ├── metadata.json           标题、时间和所用模型：只有两百来个字节
    ├── session.lock            由打开这个会话的进程持有
    └── tool-output/            过长的输出，留给模型去读
```

`<工作区键>` 是工作区绝对路径把各级目录用 `-` 连起来的结果 —— `/Users/me/projects/api` 是
`-Users-me-projects-api` —— 看一眼目录列表就知道哪个是哪个项目，路径也不会跑出存储根之外。目录名里放不下的
其他字符同样换成 `-`，特别长的路径用一小段摘要代替末尾。用 `-` 连接可能让两个不同的路径读起来一样
（`/a-b/c` 和 `/a/b-c`）；目录里的 `workspace.txt` 记着它属于哪个路径，发现名字被占用的那个项目会继续使用
以路径的 URL-safe base64 命名的目录，那个名字一定是它自己的。

`data.jsonl` 是只追加的 —— 每条记录都写着它的父节点，于是对话是一棵**树**而不是一个列表。
`metadata.json` 是会话列表读的小文件，所以列会话列表从来不需要解析对话内容。它只在会话开始、重命名和所用模型
变化时写入 —— 不是每条消息都写 —— 所以无论对话多长它都一样大，而且复制或移动会话目录时它跟着走。一个会话
多久没用过，看的是对话文件本身。崩溃可能截断最后一行，那一行会被忽略；而其他位置损坏的行会报错，
不会被悄悄丢掉。

从来没收到过消息的会话不会留下任何东西：在项目里打开 ZettCode 时，在真正存下第一条记录之前不会为它建目录；退出一个没用过的会话会删掉它的目录（如果项目目录因此变空，也一并删掉）；下次启动还会清理被强行关闭的终端没来得及收拾的空目录 —— 别的 ZettCode 正开着的永远不碰。用 `/title` 起过名的会话有标题要保留，所以不会被删。

::: details 旧版本留下的会话
旧版本用路径的 URL-safe base64（`L1VzZXJzL21l…`）给工作区目录命名。ZettCode 第一次打开这样的工作区时，会一步把
目录改名成可读的名字，所以没有复制，也不会出现移到一半的状态。如果改名做不了 —— 其中某个会话正被另一个
ZettCode 打开，或者目录里有文件正被占用而系统拒绝改名（Windows 就会）—— 目录保留旧名字，照旧使用；下次启动
再试。

旧版本为整个工作区只维护一个 `metadata.jsonl`，并且每条消息都往里追加一行，所以它能涨到几千行。
现在没有任何东西再写它。ZettCode 第一次看到某个没有自己 `metadata.json` 的会话时，会读取那个文件里
记录的内容 —— 标题和时间 —— 并存进该会话的目录，所以每个旧会话只迁移一次，之后不会再为它去翻旧文件。
旧文件原样保留、绝不会被修改；等你不再需要退回旧版本时可以自己删掉它。损坏的 `metadata.json`，或者属于
另一个会话的（目录被复制后改了名），会被直接重建。
:::

### 会话用哪个模型

每个会话都会记住它上一次用的模型。一轮对话结束时 —— 不管怎么结束，被停止或出错的那一轮也用过这个模型 ——
如果会话的 `metadata.json` 里还没有这个模型的名字，ZettCode 就把它写进去。所以切换模型只多一次很小的写入，
而普通的一条消息一次都不写。

恢复会话 —— `/resume`、`/fork` 或 `zettcode --resume` —— 会切回那个模型，并且在对话里说明：

```text
──────── Model set to GPT-4o, the one this session last used. ────────
```

- 用 `/model` 切换不算“使用”：在那个模型上发出消息之前不会记录任何东西。
- `/btw` 旁路提问不属于这段对话，不会记录。
- 从没记录过模型的会话 —— 旧版本留下的，或还没有跑过一轮的 —— 保持你打开它时选中的模型。
- 如果记录的模型已不在你的配置里，或者有两个条目显示同一个名字、无法判断指的是哪个，就保持当前模型并说明
  （`This session last used … which is not in your configuration; staying on …`），而不是乱猜。
- 记录的名字是模型选择面板里显示的那个（设了 `display_model` 就是它）。如果你在两次运行之间改了配置 ——
  比如给原来没有 `display_model` 的条目加了一个 —— 按旧名字记录的会话仍然能找到它。
- `/fork` 从原会话正在用的模型开始。

### 过长的工具输出

当一条 shell 命令的输出多到放不进一次回复时，模型会看到开头和结尾，并被告知完整输出在哪里。不是 ZettCode
自带的工具也一样对待 —— MCP 服务器、子 agent、插件返回的结果超过我们自己的工具所能返回的量时，同样只留下开头和
结尾，完整内容放进同一个地方，这样一份很长的回答不会占满会话之后每一次请求的上下文。两种情况里，输出都保存在
`~/.zettcode` 下该会话自己的 `tool-output/` 目录里，而不在你的项目中，所以它不会出现在 `git status` 或
搜索结果里，会话被删除时它也一起消失。早期版本留在你项目里的 `.zett-tool-output` 目录不会被移动或删除，
可以放心自行删掉（也可以加进 `.gitignore`）。

::: tip 为什么是树
唯一的写操作就是追加，所以保存一轮对话不会重写历史。它还顺带带来两个你能感知到的好处：
**恢复**就是从最新一条往前走到根，**压缩**是往树里加一条摘要、让后续请求在那里截断，而不删掉
任何东西。
:::

## 离开与回来

退出时会打印回来的路：

```
resume this session: zettcode resume 01a10b75 --workspace ~/projects/api
```

在程序里，`/resume` 会弹出这个工作区最近的会话（新的在前，带标题和上次变动距今多久）；
在面板里直接输入即可按标题或 id 搜索，框里为空时就是全部会话；在第一行按 `↑` 光标进入搜索框，
在搜索框里再按 `↑` 跳到最后一行；`Esc` 先清空搜索，再按一次才关闭面板。
`/resume <id>` 跳过面板直接打开。你当前在哪个会话，顶栏里写着。

`/new` 开一个新会话，当前对话留在磁盘上。`/clear` 只是清屏，会话继续，模型仍然记得之前的轮次。

### 例子：接着昨天的工作做

在同一个工作区启动，然后选择之前的会话：

```bash
zettcode -w ~/projects/api
```

在输入框中输入 `/resume`，用 `↑` / `↓` 选中目标对话，再按 `Enter`。
之前的消息会替换当前 transcript，接着就可以说“从上次失败的测试继续”。

已经知道 id 时，可以跳过列表：

```bash
zettcode --workspace ~/projects/api --resume 01a10b75
```

把路径和 id 换成自己的。直接运行 `zettcode` 默认开始新会话，不会自动恢复上一条。
如果找不到 id，先检查工作区：即使文件相同，两份 checkout 的会话列表也是分开的。

## 同一时刻只有一个进程

一个会话同一时刻只能在一个 ZettCode 进程里打开。打开它要先拿到一把**锁**——会话目录里 `session.lock` 上的操作系统文件锁——
只有拿到锁的进程才能往这个会话里写。没有这把锁的话，两个终端在同一个会话上续聊，各自按自己对"对话走到哪了"的理解往里追加，
对话就会在两边之后分叉。

锁跟着进程走，不管进程怎么结束：正常退出、崩溃、`kill -9` 都会释放它，所以不会留下需要手动清理的过期锁。新建会话、恢复或 fork 时锁会跟着转移。

如果你恢复的会话正被别的进程打开，你仍然可以**读**它，但输入框会变成一把小挂锁加上“read-only”字样，没有箭头，也没有提示：

```text
  ◈ zettcode  Fix the parser · ~/projects/api
  ……对话内容，保持打开时的样子……

 ┌──────────────────────────────────────────────────────┐
 │                          🔒                          │
 └──────────────────────────────────────────────────────┘
   ● ready
```

- **能输入什么。** 只有斜杠命令：输入 `/` 后，一个小小的 `⊘` 会出现在原来箭头的位置。其他内容都不接受，粘贴和图片也不行，`Backspace` 仍然可以清掉原有的内容。
- **拒绝什么。** 一切会写入这个会话的操作：发消息、`/btw`、`/title`、`/compact`，以及第一次回答后自动生成标题。被锁住的会话也不会出现在其他会话的
  [互发消息](/zh/guide/messaging)列表里，所以没人能给它发消息、让它转成一次写入。
- **怎么出来。** `/new` 开一个你自己的会话，`/fork` 把这段对话带进一个新会话。或者等一等：ZettCode 每隔几秒会再试一次，
  对方一放手，它就**重新读取这个会话**——这样对方写入的内容就在屏幕上了——并解锁输入框。在锁上按 `Enter` 会立刻重试。

`/fork` 会把当前对话带进一个新会话，并在那里继续。想换个方向、又不想丢掉走到这里的这段对话时用它：
原来的会话完全不受影响，每条消息都留在原地，新会话是接着它的进度另起的一条对话。

带过去的是"下一次请求本来就会发送的内容"：最新的压缩摘要，以及它之后的消息。所以被压缩过的对话会
fork 成"模型仍在阅读的那部分"，而不是一个满是已被摘要取代、之后每轮都会被跳过的消息文件。新会话会
记下自己来自哪个会话，标题也接上 `(fork)`，这样会话列表里两条能区分开。

这些信息会直接留在对话里，不需要你记住：

```text
Forked into a new session: "Fix the parser (fork)" · 01a12dd8-2d6d-70b2
resume this session: /resume 01a12dd8-2d6d-70b2
back to the previous session: /resume 01a10b75-c3a1-4d2e · "Parser rewrite"
from a shell: zettcode resume <session id> --workspace ~/projects/api
```

这条通知里也写上了你离开的那个会话：那段把工作带到这里的对话就在里面，回去只需要一次 `/resume`，
而它的 id 只有这里写着。两条应用内命令都列出来，是因为它们用在不同场合；命令行那条用的是占位 id
（两个会话都适用），并带上工作区 —— 会话存储按工作区分开，光有 id 在另一份 checkout 里没有意义。

## 标题

第一次回答之后，代理会用一次很小的模型调用生成一个四五个词的标题，存进该会话的 `metadata.json`。
会话面板和顶栏显示的就是它。

`/title users endpoint` 可以自己命名，而且这个名字会保留：自动命名永远不会覆盖已经有标题的
会话，所以你在第一条消息之前起的名字不会被冲掉。

例如，输入 `/title 修复 users 分页`。不带参数的 `/title` 会报告当前标题。
没有标题的会话显示为 `New session`，及时起名能让较长的列表更容易查找。

## 导出

`/export report.html` 会把整个会话 —— 每一轮、工具调用、耗时、压缩摘要，以及当前的上下文 ——
写进一个独立的 HTML 文件，可以直接在浏览器里读、作为记录保留、或贴进 review。不带路径时，
文件落在工作区里，名字是 `zettcode-<会话 id>.html`，并告诉你位置。

页面左侧是一列轮次，右侧是选中轮次里的事件：每一条都带着当初写入的原文、写入时间，以及它的
开销。长内容（系统提示、成片的工具输出）默认折叠，展开后在自己的区块里滚动，不会把页面撑长。
侧栏的最后一项是**当前上下文**，所以这个文件同时回答了“说过什么”和“模型现在带着什么”；
压缩过的会话会在那里显示 checkpoint，重复出现的系统指令只做指向而不再重复打印。

导出的页面不需要网络也不需要服务器：样式和脚本都内联在里面。

### 例子：保存并分享报告

在 ZettCode 内输入 `/export review.html`，再从文件管理器或浏览器打开提示中的文件。
相对路径以工作区为基准；绝对路径可以保存到其他目录，必要时会创建父目录。

`/btw` 交流不会进入导出的历史或模型上下文，但恢复会话时仍会显示在 transcript 中。
HTML 是当时的快照，之后继续对话不会自动更新它，也不能用 `/resume` 把 HTML 导入成会话。

::: warning 分享前先检查
导出可能包含源码、提示词、文件路径和带有私人信息的工具输出，发给别人前应先检查。
如果想备份可恢复的会话，应复制这个工作区对应的会话存储目录。
:::
