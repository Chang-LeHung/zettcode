# 会话

一个会话就是一段对话，保存下来，好让你回来：问了什么、答了什么、跑了哪些工具。事件边产生边写入，正常退出
不会删掉它们。

## 存在哪里

全部放在 `~/.zettcode/sessions` 下，先按工作区分组：

| 路径 | 里面是什么 |
| --- | --- |
| `<工作区键>/` | 每个工作区一个目录：绝对路径把各级用 `-` 连起来，所以 `/Users/me/projects/api` 是 `-Users-me-projects-api`。 |
| `<id>/data.jsonl` | 对话本身，只追加。每条记录写着父节点，所以它是一棵树：恢复就是走回根，压缩加一条摘要而不删任何东西。 |
| `<id>/metadata.json` | 标题、时间和模型。会话开始、改名和换模型时写入 —— 不是每条消息都写 —— 所以列表从不需要解析对话。 |
| `<id>/session.lock` | 由打开这个会话的进程持有。 |
| `<id>/tool-output/` | 过长的命令输出，不留在你的项目里。 |

从来没收到过消息的会话不会留下任何东西：没用过的会话在退出时删掉目录，下次启动还会清理被强行关闭的终端
留下的空目录。用 `/title` 起过名的会话会保留。

恢复会话会把上次用的模型和推理强度放回去，并在对话里说明。配置里已经没有那个模型、模型不接受那个档位之类的
情况，都在[模型与上下文](/zh/guide/models)里。

## 回来

退出时会打印回来的路，照抄一下就行：

```
resume this session: zettcode resume 01a10b75 --workspace ~/projects/api
```

| 在哪 | 命令 |
| --- | --- |
| ZettCode 里，从列表挑 | `/resume` |
| ZettCode 里，按 id | `/resume 01a10b75` |
| 从 shell | `zettcode -r 01a10b75 -w ~/projects/api` |

`/resume` 的面板列出这个工作区最近的会话，新的在前，输入即可按标题或 id 过滤。直接运行 `zettcode` 总是开新
会话，不会自动恢复上一条。两份 checkout 的列表是分开的，哪怕文件一模一样，所以找不到 id 时先看看工作区。

`/new` 开一个新会话，当前对话留在磁盘上。`/clear` 只是清屏，会话和它对之前轮次的记忆都还在。

## 分叉

`/fork` 把当前对话带进一个新会话，并在那里继续。原来的会话完全不受影响 —— 每条消息都留在原地 —— 所以想换
个方向又不想丢掉走到这里的那段对话时，用它。带过去的是下一次请求本来就会发送的内容：最新的压缩摘要，以及它
之后的消息。新会话接过原标题并加上 `(fork)`，对话里会写明两个会话和回到各自的命令。

## 标题

第一次回答之后，代理会用一次很小的模型调用生成一个四五个词的标题并保存。`/title users endpoint` 可以自己
命名，自动命名永远不会覆盖你起的名字。不带参数的 `/title` 报告当前标题。没有标题的会话显示为
`New session`。

## 导出 {#导出}

`/export report.html` 把整个会话 —— 每一轮、工具调用、耗时、压缩摘要，以及当前的上下文 —— 写进一个独立的
HTML 文件。样式和脚本都内联在里面，所以不需要网络，也不需要服务器。不带路径时，文件落在工作区里，名字是
`zettcode-<会话 id>.html`，并告诉你位置；相对路径以工作区为基准。

页面左侧是一列轮次，右侧是选中轮次的事件，最后一项是当前上下文。`/btw` 的交流不在里面。这个文件是快照，
也不能用 `/resume` 导入：想备份可恢复的会话，复制 `~/.zettcode/sessions` 下这个工作区的目录。

::: warning
导出可能包含源码、提示词、文件路径和带私人信息的工具输出。发给别人之前先读一遍。
:::

## 同一时刻只有一个进程

一个会话同一时刻只能在一个 ZettCode 进程里打开。打开它要在 `session.lock` 上拿一把操作系统文件锁，只有拿到
锁的进程才能往里写；没有这把锁，两个终端在同一个会话上续聊，各自按自己对“对话走到哪了”的理解追加，对话就会
在两边之后分叉。锁跟着进程走，不管进程怎么结束，所以不会有需要手动清理的过期锁。

如果恢复的会话正被别的进程打开，你仍然可以读，但输入框会变成一把挂锁和 “read-only” 字样。斜杠命令照常可用；
任何写入这个会话的操作都被拒绝，包括发消息、`/btw`、`/title` 和 `/compact`，这个会话也不会出现在
[`@` 消息](/zh/guide/messaging)里。`/new` 开一个你自己的会话，`/fork` 把这段对话带进一个新会话。ZettCode
每隔几秒会再试一次，对方一放手就重新读取这个会话；在挂锁上按 `Enter` 会立刻重试。

## 过长的输出

一条 shell 命令的输出多到放不进一次回复时，模型看到的是开头和结尾，并被告知完整输出在哪里。不是 ZettCode
自带的工具 —— MCP 服务器、子 agent、插件 —— 也照同一规则处理，所以一份很长的回答占不满会话剩下的上下文。
输出保存在该会话的 `tool-output/` 目录里，不在你的项目中，不会出现在 `git status` 或搜索结果里，会话没了它
也没了。早期版本留在项目里的 `.zett-tool-output` 目录可以放心删掉。
