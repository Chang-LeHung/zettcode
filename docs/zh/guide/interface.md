# 界面

屏幕是一个固定的框架，中间是滚动的对话。输入框留在下方，对话占用剩余空间；
命令面板打开时，会临时覆盖对话区的下半部分。

```
  ▐ zettcode  New session · @api · ~/projects/api   DeepSeek Pro · high  ← 头部
 ─────────────────────────────────────────────────────────
 ● Read src/api/users.py                                ← 对话区
 ● Edited src/api/users.py (2 edits) +24 -6             （可滚动）
 ● Ran pytest tests/test_users.py
 ─────────────────────────────────────────────────────────
   ▸ 弹窗出现在这里：模型 / 上下文 / 会话                  ← 面板
 ─────────────────────────────────────────────────────────
   /model  /resume  /context                              ← 补全候选
 › 给 GET /users 加上 limit/offset 分页                    ← 输入框
   ● ready  ↑18.4k ↓900 · ctx 12.3%                       ← 状态行
```

## 头部

左侧是程序名、**会话**（它的标题——还没有标题时是 `New session`；开启[会话互发消息](/zh/guide/messaging)时还有别的会话用来找到它的名字，如 `@api`）和工作区（路径会压缩到最有用的末尾部分）。标题太长会被截短，给后面的内容留位置；整行还是放不下时，先被截掉的是工作区，因为它在会话打开期间不会变。右侧是**下一次**请求会用的模型和推理
档位，所以切换模型在发送之前就能看到。切换推理档位时，右上角会播放一段几秒的动画：一条每格代表一个档位的细线，从你离开的档位填到你选中的档位，一道柔和的光先扫过细线、再扫过档位名。颜色表示它在刻度上的位置，而不是某种状态——低端是主题的强调色，高端是主题的错误色，中间平滑过渡，所以 `ultra` 是红的。动画淡入淡出，不会突然出现或消失，结束后把那一角还给原来的内容。请求正在跑时（那时该动的是等待行）与 reduced-motion 下都不会出现，但档位照样改变、转录里也照样有记录。

## 终端标签

启动时窗口标题是 `◈ zettcode · New session`，会话有标题后会自动替换
`New session`。使用 `/title` 重命名、恢复其他会话或新建会话时都会更新。
macOS 和 Linux 的前台进程名也会显示为 `zettcode`，不再是 `python3`；
iTerm2 标签里括号中的任务名读取的就是这个进程名。

VS Code 默认显示的是**进程名**，不是程序设置的窗口标题。要显示 ZettCode
标记和会话名，打开命令面板的 **Preferences: Open User Settings (JSON)**，
把下面两项加到已有配置对象中：

```json
{
  "terminal.integrated.tabs.title": "${sequence}",
  "terminal.integrated.tabs.description": "${process}"
}
```

这会影响所有集成终端。手动重命名的标签优先级更高；如果仍显示旧名字，
可以通过终端的 **Rename** 操作重置名称。ZettCode 不会自动改你的编辑器配置。
`◈` 是文字形式的品牌标记；终端输出无法把 VS Code 左侧的独立图标替换成
我们的像素 SVG，真正的自定义图片图标需要编辑器扩展支持。

## 对话区

每种输出都有自己的行，按发生顺序排列：

- **你的消息**用 `›` 和一条底色标出。
- **思考**默认折叠成一行，`Ctrl-T` 或单击展开最新的一段。
- **工具调用**读起来像日志 —— `Read src/app.py`、`Ran pwd`、`Edited app.py (2 edits) +24 -6`、
  `Wrote src/new.py +40`、`Searched TODO in src`。编辑新增的行画成绿色、删除的行画成红色（调用进行中或
  已结束都一样），写文件会说明文件现在有多少行。编辑或写文件成功之后，这一行在标题下面显示**改动本身**，
  取代工具那句一行的回答：

  ```text
  ✓ Edited app.py (1 edit) +2 -1  0.0 s ▸
    └ - x = 1
      + x = 2
        keep
      + y = 3
  ```

  删掉的行是红色，新增的行是绿色，改动前后各留一行不变的行以便定位；一次调用里有多处编辑时用
  `edit 1 of 3` 隔开。写入的文件同样显示，**每一行都是新增**：调用里只有新内容、没有被覆盖的旧内容，
  所以没有什么可以标成删除。失败的编辑或写入显示它的错误，因为什么都没有改。默认显示前五行，其余点击展开（展开后
  最多四十行）；过长的行会在行宽处截断，不会换行。其他输出同理；永远不会把 JSON 直接倒出来。
- **工具行只用几种颜色**，长对话也不会花：薰衣草紫表示 agent 查看或运行的一切（读取、搜索、图片、命令、计划），黄色表示写入和编辑（不用绿色，绿色是 diff 里新增的行），
  红色表示删除（以及任何失败的调用），青色表示委派的子 agent，柔紫色表示和其他会话说话。主题文件的 `[tools]` 可以逐项修改。
- **本次请求改了哪些文件**会在请求结束时列出一次，放在 `Processed for …` 那行的上面，**只有改了文件才会出现**：

  ```text
  Changed src/app.py +4 -1          <- 一个文件：一行

  Changed 3 files                   <- 多个文件：一个简短的列表（最多八行，其余写 "and N more"）
    src/app.py +4 -1
    src/new.py +40
    old.py deleted
  ```

  同一个文件不管改了几次都只算一次，数字是总和；工作区里的路径显示成相对路径。只统计**成功**的编辑、
  写入和删除 —— 失败的调用什么也没改 —— 被中途停止的请求也会报告它已经做完的部分。用 shell 命令改的文件
  （`sed -i`、格式化工具）看不到：程序只知道自己的文件工具做了什么。
- **回答**按 Markdown 渲染：标题、列表、引用、链接、**粗体**、*斜体*、`行内代码`、带语法
  高亮的代码块，以及没有外框、用逐列横线分隔、能正确处理中日韩宽字符的表格。HTML 实体按它
  所指的字符显示：`&nbsp;` 是一个缩进格，`&lt;` 就是一个尖括号。
- **正在运行的请求**是钉在对话区最下面的一行：`✦ Processing (8s · ^C/Esc to interrupt)`。思考、工具调用、
  回答都写在它上面；请求结束（回答完、报错、或被你 Ctrl-C 停掉）时，同一行变成
  `Processed for 12s · 22:53`。整屏只有这一行在动：它的图标和扫过这个词的高光一起脉动 ——
  动一秒、停一秒 —— 而计时和停止键就写在旁边的括号里，用 notice 那种灰，按整秒、整分跳。如果模型沉默了二十秒、而且没有别的东西在跑，
  这一行会用警告色说出来 —— `✦ Processing (47s · nothing from the model for 47s · ^C/Esc to interrupt)` ——
  这样一个没有进展的请求就不会被当成只是慢。它只是说出来，不会替你做任何事：推理模型在第一个字之前想几分钟是正常的，
  是否按 `Esc` 由你决定。跑几分钟的命令不算模型沉默，不会触发这句话。
  请求运行五秒之后，这个词下面会出现一条小提示（同样的灰色，挂在和工具结果相同的 `└` 上）—— `└ Tip: /btw <question> is answered on the side and never
  joins the conversation.` —— 之后每十五秒换下一条。马上就回答的请求不会出现提示，结束后的那一行也不留提示。
  每个请求都从下一条开始，所以你每次看到的都不一样；在 `[transcript]` 下设置 `tips = false` 可以关掉。
- **没有正常结束的回复**后面会跟一行说明原因（错误色），免得模型写到一半的内容被当成答案：它碰到了**输出上限**、provider 把它**截断**或**暂停**了、**上下文窗口**满了、或者模型**拒绝**了（附上 provider 的原话，以及它想运行但因此没有运行的工具）。有办法时这行会直接说 —— `/continue`、`/compact`、`/model` —— 以后再打开这个会话时也会显示同样的一行。
- **请求失败**会在对话里用错误色说明原因：库报告了什么，以及括号里服务端的回答 ——
  `error: Provider stream request failed (HTTP 404: The model gpt-9 does not exist — check the model id and the address with /config)`。
  token 被拒绝、模型不存在、地址连不上时，还会告诉你该看哪项设置。服务端回复里任何像密钥的内容都会被替换成 `…`，
  所以报错可以直接贴进 issue。请求以空回复结束时也会说一声，而不是只留下一行时间。
- **提示**（复制了多少字符、拒绝了哪条命令、导出到哪个文件）是灰色的一行。

`Page Up` / `Page Down` 和滚轮滚动对话。终端每发来一个滚轮事件就滚一行，转得再快也一样；单个画面最多只移动半屏，
所以触控板一甩不会越过你还没看到的内容。如果你的鼠标觉得太慢，可以设置 `transcript.mouse_scroll_speed`（见[配置参考](/zh/guide/config)）。
向上滚动时会出现 `↓ back to bottom` 徽标；按 `Esc`
或点它回到最新一行，视图会重新跟随对话末尾。

请求正在跑的时候，`Esc` 和 `Ctrl-C` 一样会把它中断——“要退出这件事”的那一下，不该取决于是不是记得住外壳把哪个键留给了它。

## 输入框

`›` 后面就是你打字的地方，草稿变长时它会跟着长高，最多占屏幕的一部分。

- **Enter** 发送，**Alt-Enter** 或 **Shift-Enter** 换行。
- **`/`** 打开命令菜单，**`@`** 打开资源菜单（你的 skills、文件，以及其他正在运行的会话，见[会话之间互发消息](/zh/guide/messaging)）。`↑` / `↓` 选择，`Enter` 或
  `Tab` 填入，`Esc` 关闭。
- 粘贴的长文本（超过 512 字符，或高到输入框放不下）会变成一个 `[pasted text 6012 chars]`
  芯片。**Backspace** 一次删掉整块，发送时会还原成完整文本。
- **Ctrl-V** 会把桌面剪贴板里的图片变成 `[image #N]` 芯片。文字和图片之间保持你书写的顺序。
  见[图片与粘贴](#图片与粘贴)。
- `/命令` 和 `@资源` 只有**真实存在**才会着色：命令必须存在、而且是草稿的第一个词（命令只在那里生效）；
  资源必须真的存在。其余情况 —— 句子里的 `/usr/bin`、`@某人` —— 都只是普通文字，**Backspace**
  一次只删一个字符。真实存在的才会整个删掉。

## 请求运行时输入

不必等模型停下来。它在干活时你直接打字并回车，ZettCode 会问你这条消息是什么 —— 光看文字分不出来：

```text
You sent a message while ZettCode is working. What should it do?

› then open a pull request

▸ 1. Follow up  send it after this request finishes (f)
  2. Steer      hand it to the agent now; it replaces the rest of the current task (s)

enter choose · f follow up · s steer · esc keep editing the draft
```

`f` 和 `s` 直接选中对应的一行，`Enter` 采用高亮的那一行（**Follow up**，也就是不会打断任何东西的那个），
`Esc` 关闭提问并把草稿留在输入框里，所以回车按早了也没有损失。只有一种答案可能时 —— 比如正在跑
`/compact` 这类命令，它没法被引导 —— 就不会问，消息直接作为 follow-up 等着。

### Steer（引导）：改变它正在做的事

引导消息会进入输入框上方的 `↳ steer` 列表。代理在下一个安全点 —— 当前这批工具跑完之后 —— 读到它，
并丢掉当前任务剩下的部分去照它做。最多排 8 条。它是给**同一个任务**的新指令，不会撤销已经完成的编辑。

两个列表每条消息都只占一行。放不进一行的消息会被截断并以 `…` 结尾，首行之后还有更多行的消息也一样
（粘贴的一大段只显示首行和 `…`）；实际发出的仍是完整文本。

你在列表里看到它的时候，代理已经拿到了，而且代理没有提供取回消息的办法，所以**引导消息不能编辑、删除或调整顺序**。
如果你还拿不准要不要发，就把它作为后续消息发送：后续消息一直在你手里。

### Follow up（后续）：接下来做这个

后续消息在自己的 `• follow-up` 列表里等待，这个列表紧贴在输入框上方。对话顺利结束之后，它们各作为一条独立的消息发出：
一次一条，按列表里的顺序，前一条做完才开始下一条。最多等 8 条。引导消息和后续消息可以同时存在：引导列表在上面，
下面所有的按键都只作用于后续消息。

因为后续消息还在你手里，所以可以修改。`Option` 就是 Mac 键盘上标着 `⌥` 的那个键（其他键盘上是 `Alt`，提示里也会写成 `alt`）：

| 按键 | 作用 |
| --- | --- |
| <kbd>Option</kbd>+<kbd>↑</kbd> / <kbd>Option</kbd>+<kbd>↓</kbd> | 没有高亮时：进入列表，`Option-↑` 落在离输入框最近的一行，`Option-↓` 落在第一行。**有高亮时：移动这条消息**，前移或后移一位，高亮跟着它走。 |
| <kbd>↑</kbd> / <kbd>↓</kbd> | 有消息高亮时：移动高亮；在最后一行再按 `↓` 回到输入框。没有高亮时它们仍然是输入框的，和平常一样。 |
| <kbd>Enter</kbd> | 把高亮的消息从列表里取出来放进输入框去修改；再次发送会放回**它原来的位置**，而不是末尾。 |
| <kbd>Ctrl</kbd>+<kbd>S</kbd> | **现在就作为引导（steer）发出。** 高亮的消息离开后续消息列表，作为引导消息交给正在运行的请求，在它的下一个模型或工具边界被采纳 —— 适用于那条后来发现很紧急的消息。图片一起带过去。做不到时会说明原因：没有正在运行的请求（停止后列表处于保留状态）、正在运行的是命令而不是回复、或已达引导数量上限；此时消息原样留在列表里。 |
| <kbd>Delete</kbd> / <kbd>Backspace</kbd> | 删除高亮的消息，它不会被发出。输入框上方那一行会说明删掉了什么。 |
| <kbd>Esc</kbd> | 取消高亮。请求照常继续；再按一次 `Esc` 才会像平时一样停止请求。 |

列表自己会说明这些按键 —— 它下面一行写着 `option+↑/↓ to select`，高亮之后会列出其余的按键 —— 所以不需要背。
输入任何字符也会取消高亮；输入框里已经有草稿时，`Enter` 不会覆盖它：先写完或清空（`Ctrl-C`）。

::: tip 在 VS Code 的终端里
VS Code 会在终端看到按键之前就改写 `Option-↑` 和 `Option-↓` —— 它发出的是 `Ctrl-↑` 和 `Ctrl-↓` ——
所以 ZettCode 把这两种写法当作同一个键，列表在那里的表现和 iTerm2 里一样。（只在存在后续消息列表时生效：
没有排队的消息时，这两个键不受影响。）
:::

::: tip 终端吞掉了 Option-↑ 怎么办
有些终端自己占用 `Option-↑`。ZettCode 认得常见的各种写法，包括 macOS Terminal 和 iTerm2 的
“Option 发送 Esc+”设置。如果你的终端仍然把这个键吃掉，请在 Terminal 里打开 “Use Option as Meta”，
或在 iTerm2 里把左 Option 键设成 “Esc+”。
:::

### 对话没有顺利结束时

`Esc`（或 `Ctrl-C`）用来停止你不想要的请求，**它只做这一件事**。后续消息是你自己的列表：停止不会把它们发出去，
也不会把它们拿走。它们留在列表里，这时列表下面写着 `held until your next reply completes`，对话里会说明暂存了几条。
你接着输入你真正想说的话 —— 等**这条**回复顺利完成，暂存的后续消息才会按顺序接在它后面发出。请求出错时同样处理。

所以后续消息只会接在一次顺利结束的对话之后。中间跑完一个旁路提问（`/btw`）不算回复，不会放行它们。
列表属于它所在的对话：`/new`、`/resume`、`/fork` 会把它们作为文字还给输入框，而不是发进一个它们不是为之而写的对话。

只有一种情况不同：代理还没来得及读到的**引导**消息，是为刚结束的那个请求写的，所以它会回到输入框，
接在你已经输入的内容后面。

例如，模型正在实现分页时，把这条作为 **steer** 发送：

> 保持现有 API 响应格式，只增加分页字段。

把这条作为 **follow up** 发送：

> 然后给最后一页加一个测试。

需要立即停止时，应按 `Esc`。

## 弹窗

需要做选择的命令会在对话之上弹出一个面板，而不是把选项打印进对话里。`↑` / `↓` 移动，`Enter`
确认，`Esc` 回到输入框，下面的对话完全不受影响：

- `/model` —— 选后续请求用的模型。
- `/resume` —— 选最近的会话，带标题和上次变动距今多久。
- `/context` —— 看当前上下文窗口被什么占着。
- `/usage` —— 看这个项目的会话按模型、按会话、按天花了多少；它占满整个屏幕。见 [Token 用量](/zh/guide/commands#usage)。
- **审批面板** —— 问你要不要执行某条 shell 命令。

`/theme` 与 `/permission` 是在几个固定的词里选一个，所以用命令菜单而不是面板：输入命令和一个空格，
`Enter` 应用高亮的那个词。`/effort` 有自己的面板：一条档位轨道，用 `←` `→` 滑动上面的小圆点。

## 审批

`bash` 是唯一会先问的工具。问不问、问多少，是一个四档的设置，请求之间随时可以用
`/permission` 调整：

| 档位 | shell 命令会怎样 |
| --- | --- |
| `deny` | 一条都不跑。模型会收到“shell 已关闭”的说明，改用文件工具继续。 |
| `ask` | 每条都等你回答。每次启动都从这一档开始。 |
| `safe` | 只读的命令直接跑，其余的仍然询问。 |
| `auto` | 每条命令都直接跑，不再询问。 |

这个设置只管 shell。文件编辑和 MCP 工具在 ZettCode 里本来就不走审批，所以 `deny`
不等于把工作区变成只读。它也不会跨重启保存：下一次启动又从 `ask` 开始。

在 `ask` 和 `safe` 下，面板会显示完整命令、它当前所在的档位，并提供：

| 按键 | 含义 |
| --- | --- |
| `y` | 这次执行。 |
| `p` | 执行，并在这个会话里记住这条命令。 |
| `s` | 执行，并且不再询问只读命令（切到 `safe`）。在 `safe` 下不提供，因为那不会改变任何东西。 |
| `a` | 执行，并且本轮剩下的任何命令都不再问（切到 `auto`）。 |
| `Esc` | 拒绝。代理会收到“命令失败”，可以据此调整。 |

`s` 和 `a` 与 `/permission safe`、`/permission auto` 做的是同一件事：无论从哪扇门进来，档位、对话里的那一行、
状态栏都一致。请求进行中时，面板里的这两个键就是调整它的方法，因为手打的命令要等请求结束。

例如，对于 `pytest tests/test_users.py`，选 `y` 表示下一条命令仍然单独审阅。
只有想在当前进程中记住这条精确命令时，才选 `p`。`a` 会给出更广的允许范围，不要只为了
关掉面板就选择它。审批记忆不会跨程序重启保存，工具也不是在 ZettCode 提供的沙箱里执行。

### `safe` 会跑什么

`safe` 只有在认出命令的每一部分都不可能改动任何东西时，才不问直接跑：一张很短的只读程序表
（`ls`、`cat`、`grep`、`head`、`wc`、`diff`…）、去掉了会执行程序或写文件的选项的 `rg` 和 `find`、
以及 `git status`、`log`、`diff`、`show` 等只读子命令，可以用 `|` 连起来。认不出的一律询问，包括
`;`、`&&`、重定向、`$(…)`，以及表之外的所有程序。

有两件事它不保证。只读命令仍然可以把工作区里的密钥打印出来，所以 `safe` 的意思是“不会改动”，
而不是“不会被看到”。另外 `git` 会读自己的配置，配置里可以指定要运行的程序：仓库自己的配置若有这类写法，
就不再信任它，而你的全局 git 配置没有检查。工作区里可能有这类文件时，请用 `ask`。

## 当模型向你提问时

有些决定不该由模型替你猜：用哪种格式、两个文件里的哪一个、要不要继续。它可以问，这一轮会
等你回答。面板只占内容需要的高度，并且会写明它想要哪种答案：

```
  Which format should I write the summary in?
       1. Markdown
   ▸ ✓ 2. Plain text
  › up/down choose, enter sends · or type an answer · esc cancels
```

- `↑` / `↓` 在选项之间移动，`Enter` 对高亮的那一行生效。单选问题会直接把它发出去（和
  `/model`、`/resume` 一样），`✓` 标出的就是回车会选的那一项。
- 多选问题则是勾选，并且多出一行 `➤ send` 用来收尾：

  ```
     ✓ 1. Summary
     ✓ 2. Diff
       3. Tests
     ➤ send (2 chosen)
  ```

  在高亮的已勾选行上再按 `Enter` 就是取消勾选；`➤ send` 会把已勾选的内容发出去。
- 选项下面就是回答行，没有额外标签：没打字时它显示快捷键提示，一开始打字就显示你输入的内容。
  所以既能选，也能用自己的话回答；而没有给选项的问题，就只剩这一行。多选的答案 = 勾选的项
  加上你在这一行补充的文字（勾选项在前，与书写顺序无关；已经勾过的那一项不会重复出现）。
- 打字时面板会切换形态：选项折起来，`▸` 标记和底色移到回答行上（因为光标在那里）；
  `↑` / `↓` 可以把选项叫回来，输入的内容仍然留在行里 —— 单选时此时不会再给任何行打勾，
  因为答案是你说的话。
- 选中的行保留一层背景色，并带一个强调色的 `✓`，一眼能看出选了哪些；光标所在的行底色更强。
- 单选时，如果你已经打了字再去选项上回车，问题那一行旁边会先出现 `one answer only` 提示；
  再按一次 `Enter` 才会用选项替换你写的内容。
- 同一次回复里问多个问题时，标题会标出 `(1 of 2)` 这样的序号，并且一个一个问：回答完当前这个，
  下一个才出现。
- `Esc`（或 `Ctrl-C`）表示不回答。模型会收到「问题被取消」，然后继续往下走，而不是一直等一个
  不会到来的回答。

和审批面板一样，它盖在对话之上，这一轮在回答之前一直挂起。
`[ask_user] enabled = false` 可以彻底拿走这个工具，那时模型只会依据已知信息作答，不再提问。

一次回复里模型可以问多个问题（它被要求一次只问一件事，而不是把它们塞进同一段）。每个问题都是
独立的面板，标题会写 `1 of 2` 这样；上一个回答完，下一个才会出现。

## 旁路提问（btw）

`/btw <问题>` 用来问一件模型凭现有信息就能回答的事 —— 「这个函数干什么？」「这两者哪个更快？」
—— 答案会像普通一轮一样显示在这里，并标上 `btw ›`，底色是它自己那一种带色调的填充，所以这条
旁白在周围的轮次里一眼就能认出来（想改色就改 [`surface_side`](/zh/guide/config#颜色)）。

它之所以是「旁路」，在于**不保留**的东西：

- 问答会写进会话文件，但永远不会重放进模型上下文，所以之后的对话不知道它发生过。
- 恢复会话时**会**重放进 transcript，并像当初那样标上 `btw ›`（你看到过那个答案，所以它回来），
  但导出（[/guide/sessions#导出](/zh/guide/sessions#导出)）里没有。
- 只提供**只读工具**。旁路期间的修改，之后的对话看不到，模型会带着错误的假设继续。

在一轮进行中提问不会被打回，而是排队等这一轮结束；它花的 token 照常计入状态行，但不会触发自动
压缩或自动命名。

例如，在修改 API 接口的任务中输入：

```text
/btw offset 分页和 cursor 分页有什么区别？
```

如果答案应该指导接下来的主任务，应改用普通消息。正在执行正常请求时，旁路问题会等待它
结束，不会同时出现第二个修改工作区的任务。

## 图片与粘贴

图片可以像普通消息一样发送，**包括请求运行期间**：作为后续消息（follow-up）时，图片会出现在它的芯片所在的位置；
作为引导（steer）时，代理收到的是一条带图片的消息。把消息取回来编辑、或者取回代理还没读到的消息时，图片会恢复成芯片。

终端没法把粘贴图片的字节交给程序，所以 **Ctrl-V** 自己去读系统剪贴板 —— macOS 上直接读
pasteboard，Linux 上用 `wl-paste` 或 `xclip` —— 并在图片应在的位置插入一个芯片。PNG、JPEG、
WebP、GIF 都会原样送达，并按芯片所在的位置作为图片部分发出，所以模型看到图片的顺序就是你写的
顺序。

这读的是 ZettCode 所在那台机器的剪贴板，所以**通过 `ssh` 时它看不到你在自己机器上复制的图片**：终端能把文字带过连接（[复制](#通过-ssh-复制)就是这样工作的），却没有办法带一张图片。所以在 `ssh` 里 Ctrl-V 根本不去读，而是告诉你原因和办法：把文件放到服务器上，用路径引用它；或者当你转发了显示、服务器的剪贴板恰好就是想要的那个时，设置 `ZETTCODE_CLIPBOARD=system`。

在没有剪贴板工具的机器上（一台干净的 Linux 服务器既没有 `wl-paste` 也没有 `xclip`），Ctrl-V 会提示 `no image on the clipboard`。工具缺失、无法运行或三秒内没有响应，都不会让会话结束。

芯片本身是文本，这带来两个结果：

- 恢复会话时会显示 `[image #3]` 而不是图片，也不会重发；
- 配置了 `multimodal = false` 的模型会直接拒绝并提示，而不是发出去才失败，而且不会拿到
  `view_image` 工具。

其他粘贴仍然走终端自己的粘贴键（macOS 是 `Cmd-V`，别处是 `Ctrl-Shift-V` 或 `Alt-V`）。有些
终端会把图片**当文本**粘贴（VS Code 的集成终端会把图片转成 base64），这种情况也认得：
`data:image/…;base64,` 开头的串，或者能解码出已知图片格式的 base64，都会变成同样的芯片，而
不是一屏字符。

## 选中与复制

- 在对话区拖动选中，松开即复制；输入框上方那一行会短暂居中显示一颗高亮的小药丸 `✓ copied 42 chars to clipboard`，
  随后被你接着输入的内容取代。屏幕上只有这颗药丸能说明复制发生了，所以它有自己的底色；底色只包住文字本身，不会铺满整行。
- 双击选中整行，<kbd>Shift</kbd>+单击扩大选区。
- 在其他地方（弹窗、列表、头部）拖动，会复制画在那里的文字。
- `Ctrl-C` 复制当前选中并清除；没有选中时，它用来停止正在跑的请求，或者清空草稿。

### 通过 `ssh` 复制

当 ZettCode 跑在你用 `ssh` 登录的服务器上时，你要粘贴的剪贴板是**你自己那台机器**的，而不是服务器的。
服务器上的剪贴板工具只能碰到服务器的剪贴板，所以 ZettCode 在这种情况下不用它，而是请你的终端去复制
（一条 [OSC 52](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html) 转义序列），它和程序打印的其他内容一样经由连接传到你面前。
这时药丸写的是

```text
✓ sent 42 chars to your terminal's clipboard
```

这里特意写 “sent” 而不是 “copied”：程序在另一台机器上，看不到你的终端是否接受了它。不少终端会先询问，或默认拒绝。

| 终端 | 需要什么 |
| --- | --- |
| iTerm2 | 打开“允许终端里的应用访问剪贴板”的那个设置 —— 在 Settings → General → Selection 里，“Applications in terminal may access clipboard” |
| kitty、Alacritty、Ghostty | 什么都不用做：它们默认允许程序*写入*剪贴板 |
| WezTerm、Windows Terminal | 支持 |
| tmux | 在 `~/.tmux.conf` 里设置 `set -g set-clipboard on` —— tmux 默认的 `external` 不接受里面程序发来的 —— 或者 `set -g allow-passthrough on` |

不支持 OSC 52 的终端会直接忽略它，文字哪里也不会去。这时请用那个终端自己的选择来复制：拖动时按住它的修饰键（<kbd>Shift</kbd> 或 <kbd>Option</kbd>）。

ZettCode 靠环境变量判断往哪里复制：`SSH_CONNECTION`、`SSH_CLIENT` 或 `SSH_TTY` 表示它在连接的另一头。
判断错了的时候 —— 比如 `sudo` 丢掉了这些变量，或者你转发了 X 显示、想要的恰恰是服务器的剪贴板 ——
用 `ZETTCODE_CLIPBOARD=terminal` 或 `ZETTCODE_CLIPBOARD=system` 明确告诉它。

## 状态行

左半部分是“现在在干什么、花了多少”；右半部分一直显示两个值得记住的键（`^C/Esc to interrupt`、`^D exit`）。

| 片段 | 含义 |
| --- | --- |
| `●` / 闪动的 `✦` | 点是空闲，闪动的星是正在干活。 |
| `ready`、`running` | 当前状态 —— 也可能是一句临时说明，比如正在跑的命令或复制了多少字符。 |
| `· deny`、`· safe`、`· auto` | shell 权限不是默认的 `ask` 时显示的档位。 |
| `↑18.4k ↓900` | 本次会话发给模型的 token 数，以及模型生成的 token 数。 |
| `71.2% cached` | 输入里由 provider 缓存命中的比例。 |
| `74 tok/s` | 按模型耗时平均的生成速度。 |
| `ctx 12.3%` | 最新一次请求占满了模型上下文窗口的多少。 |

这些数字都来自 provider 自己的计数，在每次模型调用后累加 —— 本地不做估算；恢复会话时会用分支
上存下来的用量做起点。
