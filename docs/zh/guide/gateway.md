# 网页网关

`zettcode gateway` 为这台机器上的后台 agent 提供一个网页。它本身不是 agent：左边是聊天列表，中间是 daemon 和会话，
右边是对话。用手机也能打开——终端留在代码所在的地方，页面跟着你走。

```sh
zettcode gateway                    # 在当前终端里运行，Ctrl-C 结束
zettcode gateway --port 9000        # 一样，只是换个端口
```

默认监听 `127.0.0.1:8765`。运行一次，然后打开它打印出来的地址。

## 在后台运行

```sh
zettcode gateway start              # 脱离终端运行，立刻返回
zettcode gateway stop               # 停掉正在运行的那个
zettcode gateway restart            # 先停，再按原来的设置启动
```

`start` 会打印页面地址和登录方式，把输出写进网关目录（默认 `~/.zettcode/gateway`，可用 `--directory` 改）里的
`gateway.log`，等页面能访问之后才返回。不带参数的 `restart` 会沿用正在运行那个网关的设置——host、port、token、roots——
所以重启不会悄悄换掉地址或让已保存的登录失效；要改就带参数（`zettcode gateway restart --port 9000 --token new`）。

只有被认出确实是网关的进程才会被结束：`stop` 先检查命令行，所以过期记录或被复用的进程号不会误杀别的东西。
没有在运行时也不算错误：`stop` 会直说，并以 0 退出。唯一的例外是进程还在、但命令行读不出来：这时 `stop` 会保留记录并以 1 退出，
而不是靠猜——那个进程可能就是网关。

## 登录与权限

- 不给 `--token` 就没有登录，网关只监听本机；页面打印的地址直接可用。
- 给 `--token`（或 `$ZETTCODE_GATEWAY_TOKEN`）时，页面会让你输入一次，之后保留一个 cookie。
- 监听本机之外（`--host 0.0.0.0`）必须有 token：没有的话，任何能连到这个端口的人都能用你的身份运行命令。
  页面是明文 HTTP，离开本机时请放在 TLS 后面。
- `-r`/`--root` 限定 daemon 可以在哪些目录里启动；默认任何目录都可以。`--no-full` 不允许页面以
  full shell 级别（没有沙箱、不询问）启动 daemon；记录过 `--no-full` 之后，可以用 `--full` 再打开。
- [桌面端](app.md) 从自己的 origin 连接。带 token 的网关会放行它；没有 token 时会被拒绝，因为
  origin 不是凭据。`--client-origin https://client.example` 可以为自己的页面再加一个 origin，同样需要 token。
  安卓端直接加载网关自己的页面，不需要在这里登记。

### 只读 token

`--read-token`（或 `$ZETTCODE_GATEWAY_READ_TOKEN`）再加一个以**只读**身份登录的 token：拿到它的人可以打开页面、查看所有对话、群聊和关系图、实时观看，但不能修改任何东西。所有修改都会被以 `read_only` 拒绝——发送消息、创建或删除群、启动/停止/删除 daemon、编辑模型或智能体——页面也会隐藏这些控件并说明原因。只读登录仍可以把会话标为已读、退出登录，但不能用目录选择器，因为它会列出本机目录，属于启动 daemon 的一部分。

把它交给只需要观察、不需要操控的人。它必须和主 token 同时存在（没有主 token 就没有“只读”可言），并且不能与主 token 相同；任何一种错误都会让网关拒绝启动。建议用环境变量：命令行参数在 `ps` 里对本机所有用户可见。重启会像主 token 一样保留它，更换 token 会让用旧 token 完成的登录全部失效。

### 指标

`GET /metrics` 以 Prometheus 能读取的文本格式返回指标，可用于仪表盘或告警。它和其他路由一样需要登录，所以采集器要把 token 作为 bearer 发送（`Authorization: Bearer <token>`）；只读 token 就够用，监控系统应该拿这一个。

```yaml
scrape_configs:
  - job_name: zettcode-gateway
    metrics_path: /metrics
    authorization: { credentials: "<只读 token>" }
    static_configs: [{ targets: ["gateway.example:8765"] }]
```

内容包括：网关版本和运行时长；按路由、方法和状态类别（`2xx`、`4xx`、`5xx`）统计的 API 请求，以及每个路由的延迟直方图；按结果（`read`、`write`、`failed`、`locked`）统计的登录尝试；当前打开的和启动以来接受过的事件连接；以及抓取时刻读取的会话数量、在线数、工作中数量和 broker 是否可达。计数保存在内存里，网关重启后从零开始，采集器会把它当作一次重置。标签只会是网关自己取的名字（路由名、状态类别），绝不会是客户端发来的路径或值，所以客户端无法通过请求奇怪的地址让表无限增长。其中没有 token、没有消息正文，也没有会话名称。

### 审计日志

网关会在自己的目录（默认 `~/.zettcode/gateway`）的 `audit.jsonl` 里追加一行 JSON，记录每一次登录、退出、被拒或失败的尝试、每一次实时事件连接，以及每一次经由它做出的修改，包括时间、用的是只读还是写权限 token、来源地址、路由和结果。单纯的读取不记录。它记录的是**发生过什么**，从不记录内容：没有 token、没有 cookie，也没有消息正文。返回服务器错误的修改带有 `"outcome": "unknown"`，因为网关无法确定它是否已经生效，不要把 500 理解成“什么都没发生”。文件只有所有者可读，超过 5 MB 后会移到 `audit.jsonl.1`，所以它保留的是最近一段，而不是全部历史。被拒的事件连接同一地址每分钟最多记一次，重连循环不会把登录记录挤出文件。如果文件写不进去，网关仍会继续响应，并在自己的日志里提示一次。

## 页面能做什么

页面会列出这台机器上的 daemon 和其他会话：在线的在前，离线的在后，每组里最近活跃的排最前。群聊像即时通讯软件一样列在最上面：打开一个群可以看到里面说过的话、成员以及谁在线，也可以在里面发言（网关不在群里时，发言会先把它加入群）。可以从页面启动、停止 daemon —— 正在工作的 daemon 停止前会要求确认 —— 停掉的会以离线状态留在列表里，直到你把它删除；删除会永久移除它和它的对话。也可以像联系人一样和它们对话：
你输入的内容以网关的名义作为消息发出，对方的回复回到同一个对话里。页面发出的消息会等对方**当前请求结束**再处理：
页面并不实时显示那个请求，所以不会改变一个你看不到的请求（终端会问你要不要 steer，页面只是等）。
网关自己也是一个会话，像终端一样在 broker 上注册，
所以 daemon 看到的是一个人的消息，而不是另一个 agent 的。它的名字是 `Web gateway`。

**图片。** 与 daemon 的对话里有添加图片的按钮，也可以把图片粘贴或拖到输入框上：每条消息最多四张，每张 4 MiB，
合计 8 MiB。较大的图片会在浏览器里先缩小到模型实际能读取的尺寸（最长边 1568 像素）；照片总是会重新绘制，这样也会丢掉文件里记录的拍摄地点等信息，
较小的 PNG、GIF、WebP 则原样发送。当 daemon 的模型不读图片时按钮是灰的；对不是 daemon、或不把对话文字当作自己提示词运行的会话也不能发图，
因为图片没有地方放。broker 只转交图片、不保存：它记下的只是这条消息带了图片。图片在 daemon 自己的对话里，页面就是从那里显示它们的。

**Config → Models** 页面可以增加、编辑和删除 `~/.zettcode/config.toml` 里的模型，做法与终端里的
[`/config`](/zh/guide/config) 相同：文件其余部分和注释保持原样，文件不接受的模型会连同文件自己给出的原因一起被拒绝，
最后一个模型不能删除。API 密钥只写不读：页面不会显示已保存的密钥，留空表示保持不变。改动对之后启动的 daemon 生效，
已在运行的 daemon 仍用启动时的模型。能登录网关的人都能修改这个文件，请保管好令牌（见上文的登录与权限一节）。
通过网关发起的修改会逐个执行，但与终端里同一时刻的 `/config` 修改互不可见：后写的一方生效，请避免两边同时改。

**Logs** 页面把 daemon 自己的日志按列表展示：时间、哪个工具以及它做了什么，每个回合的开始与结束都有标记。
可以只看工具或只看问题，也可以搜索。

网关需要一个已配置的模型，因为它的会话是真实会话，尽管它自己从不调用模型。没有模型是 `start` 唯一可能
只报错、不给页面的原因，日志里会写清楚。
