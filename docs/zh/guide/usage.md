# Token 用量

`/usage` 显示这个项目花了多少：里面的每个会话、跑过的每个模型、用过的每一天。它读的是这台机器上存着的对话：
它不是账单，也不是实时表。

```text
/usage
```

`Tab` 或 `1`、`2`、`3` 切换视图；`Esc` 或 `q` 关闭。它管的是你启动时所在的那个项目：`zettcode -w
~/projects/api` 只统计那个项目，别的不动。

## 三个视图

| 视图 | 回答什么 | 排序 |
| --- | --- | --- |
| **Models** | 哪个模型发了多少、生成了多少 | 从大到小 |
| **Sessions** | 每个会话花了多少，输入里有多少来自缓存 | 最近改过的在前 |
| **Calendar** | 哪几天在工作，哪天重 | 一周一列 |

## 数的是什么

| 词 | 数的是什么 |
| --- | --- |
| `in` | 每一声**发出去**的 token。对话每轮都要重发，所以同一段旧消息会被反复计入 |
| `out` | 模型**生成**的每个 token，含思考 |
| `cached` | `in` 里 provider 从自己缓存答的那部分，计费更便宜。是 `in` 的一个比例，不是另一笔数 |
| `reasoning` | `out` 里 provider 算作思考的那部分，是 `out` 的比例 |
| tokens | `in` + `out`。缓存和思考都已经在里面，不会重复计 |
| requests | 模型调用次数：每轮一次，加上压缩发起的那些 |
| sessions | 统计到的对话数，每个在 `/resume` 里占一行 |

上千的数字写短的：`740K`、`3.14M`。每个数字都是 provider 报上来的计数，这里没有一个估出来的值。

三个视图上方有一行，合计整个项目：

```text
All models   3.14M tokens   in 2.98M   out 159K   cached 61.07%   43 requests · 3 sessions
```

从右往左读：3 个会话里 43 次调用，生成了 159,000 个 token，发出去的那些里有 61.07% 来自缓存。`cached` 总是
两位小数；显示成横线表示 provider 没报缓存读取，很多本地端点都是这样。

## 怎么读这些条

![`/usage` 的 Models 视图：每个模型一行条](/screens/usage-models.svg)

**Models** 让输入和输出各用各的比例，都对着最大的那个模型：输出在任何模型上都只占输入的一小部分，共用一个比例
就什么也画不出来。

![Sessions 视图：每行四个时间、一个标题、两条 token 条和一条缓存条](/screens/usage-sessions.svg)

**Sessions** 的 token 条用平方根比例，小一千倍的会话在最大的旁边也看得见；旁边的数字是精确值。缓存条是普通的
0–100%，两行可以直接比。

缓存占比这一列值得看两遍。你反复回来的长会话通常留得高，因为它的开头没变、一直有缓存；总是接着别人停下的地方
开始的短会话通常低一些。换模型、压缩、长时间闲置都会把它拉低。没有什么"好"数值：拿一个会话和它自己改之前比，
不要和隔壁比。

![Calendar 视图：周为列、星期为行，格子按当天用量上色](/screens/usage-calendar.svg)

**Calendar** 一周一列，周一到周日；一行一个星期几，一格一天，按当天的 token 上色。四个深浅加一个空白覆盖所有
日子，分界点是**你自己**用过的那些天的四分位数，所以这张图看的是形状而不是大小：一天一千 token 和一天一百万
都会得到深格子和浅格子。未来的日子不画。先看下面的图例再看格子——某个深浅在一种配色里好认，换一套可能很淡。

格子下面是选中那天的这一行，再往下是 `active days`、`longest streak`、`current streak` 和 `busiest`。
`←` `→` 按周挪选中日，`↑` `↓` 按天挪。

## 数字从哪来

第一次 `/usage` 会把存着的对话都读一遍，几个 G 的时候要几秒。之后它在那个项目的会话旁边放一个小
`usage.json`，位置在 `~/.zettcode/sessions` 下；再跑只读新增的部分。删掉它，下一次 `/usage` 会重建。
`/resume` 读旁边更小的 `sessions.json`，每个会话一行。

- **一次回复只计一次**，记在它最初写进的那个会话里。`/fork` 复制对话，分叉只显示它分叉之后花的部分。
- **子 agent 的会话不计**。它的 token 算在发起它的那一轮里。
- **一天是你时区里的一天。**
- **压缩也计**，因为那是一次模型调用。
- **旧版本写的会话也算**，只要它的回复带着用量；没带的不加猜测，直接不算。

## 这一页，还是状态行？

`/usage` 覆盖项目里所有存下来的会话，一路到今天；状态行数的是这个会话，从它开始算。前者的 `cached` 是整个
项目输入的比例，后者是这一个会话的。状态行上不起眼的一个会话，在这一页里也可能是很大的一行；两个都不是账单：
实际扣了多少，看 provider 自己的面板。见[读懂状态行](/zh/guide/models#读懂状态行)。

## 看起来不对的时候

| 你看到的 | 意思 |
| --- | --- |
| 页面是空的 | 这个项目里还没有带用量的回复。没等到回答就被停掉的请求什么都没花 |
| 数字比对话大得多 | 输入每发一次就计一次 |
| 某天看着太浅或太深 | 深浅是你自己那些天的四分位数；多一个重日子，其余会重新分配 |
