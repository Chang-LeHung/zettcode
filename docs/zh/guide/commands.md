# 命令

输入 `/` 就会打开菜单，边打边过滤，`Enter` 或 `Tab` 填入高亮的那一条。需要参数的命令在名字后
面加空格和参数 —— `/title users endpoint` —— 执行任何命令都不会离开当前界面。

有固定第一个词的命令，在输入命令名和空格之后会把它列出来：`/config ` 给出 `add`、`remove`、`list`、
`providers`，`/theme ` 给出各个配色，`/permission ` 给出它的档位，`/model ` 给出你配置过的
模型。`Tab` 填入其中一项，`Enter` 选中高亮的那一项并立即执行 —— `/model ` 再按 `↓` `Enter` 就直接切换模型，不再打开选择器。
`/config` 里需要继续输入的两个词（`add`、`remove`）只会被填入。

只有列表里的名字才是命令。其他以斜杠开头的内容 —— 比如路径 `/var/log/syslog`、打错的名字、`/tmp is full` —— 都是普通文本，
和其他消息一样发给模型。是命令的时候会立刻换成另一种颜色，所以你能看出它会按哪种方式处理。

| 命令 | 作用 |
| --- | --- |
| `/help` | 列出命令和快捷键。 |
| `/new` | 开一个新会话，旧会话仍留在磁盘上。 |
| `/clear` | 清空屏幕上可见的对话，会话本身继续。 |
| `/resume` | 弹出面板选择最近的会话；`/resume <id>` 直接打开指定会话。面板里每个会话显示：更新时间、条目数、输入和输出 token 数、输入中命中服务商缓存的比例，以及短 id。终端较窄时，先省掉右边的列。 |
| `/continue` | 从中断的地方继续一个没做完的请求 —— 被 `Esc` 停掉、失败、被 provider 断开、或碰到输出上限。见[继续](#continue)。 |
| `/fork` | 把当前对话带进一个新会话，并在那里继续。 |
| `/model` | 用面板选择后续请求使用的模型。 |
| `/config` | 不用改文件就能添加、修改、删除模型，并设置它是否接受图片、上下文窗口多大、什么时候压缩：`/config`、`/config add <provider> …`、`/config remove <序号>`。见[用 /config 添加模型](/zh/guide/config#adding-models-with-config)。 |
| `/effort` | 用轨道上的小圆点选择模型的推理强度：`/effort` 打开，← → 滑动，`Enter` 应用；`/effort high` 直接设置。当前模型不支持的档位（见 [`reasoning_efforts`](/zh/guide/config#reasoning-levels-a-model-takes)）会被拒绝，并列出它支持的档位。 |
| `/permission` | 选择 shell 命令在多大范围内不用问：`/permission` 在菜单里列出各档，`/permission safe` 直接设置。`safe` 把每条命令放进只能写工作区和 `/tmp` 的沙箱里跑，`full` 用你自己的权限跑。档位属于这个会话：下次打开它就从这一档开始，新会话则从本次运行开始时的档位开始。 |
| `/harness` | 让模型自己写小的 Python 工具并运行：`/harness on` 或 `/harness off`，单独输入 `/harness` 会告诉你当前状态。默认关闭，请求进行中不接受。见[可选参数参考](/zh/guide/config#可选参数参考)。 |
| `/btw` | 问一件只在当场回答、不进入对话的事：`/btw <问题>`。 |
| `/code-review` | 请人评审尚未提交的改动：`/code-review` 评审现有的改动，`/code-review <文本>` 说明重点看什么。它写一段提示 —— 改了什么、怎么收集、评审要说出什么 —— 当成一轮对话交给模型，等同于你亲手打了一遍；会建议另一个 reviewer，起不来时模型自己评审。见[从一次评审开始](/zh/guide/daemons#从一次评审开始)。 |
| `/bash` | 在工作区里打开一个全屏命令行：`/bash` 打开空面板，`/bash git status` 打开后立即运行这条命令。有历史、Tab 补全和彩色输出；因为是你自己在敲，所以不需要任何权限确认。见[Shell 面板](#bash)。 |
| `/theme` | 按名字选配色：`/theme` 打开菜单，在菜单里移动时会预览每一套；`/theme nord` 一步切换。你自己的主题（`~/.zettcode/themes/<name>.toml`）也在菜单里。 |
| `/pet` | 选择对话上方的宠物：`/pet` 打开面板（↑ ↓ 移动时把每只宠物立即放到对话区里，`Enter` 选定，`Esc` 把原来的放回去）；`/pet whale` 一步切换。保存到 `[ui] pet`。见[宠物](/zh/guide/interface#the-pet)。 |
| `/context` | 查看上下文窗口有多满、离自动压缩还有多远、被什么占着——用条形图表示，并列出这个会话存在哪里。见[上下文窗口](/zh/guide/context)。 |
| `/usage` | 打开一个页面，看这个项目的会话花了多少：按模型、按会话统计 token，以及一张按天的日历图。见[Token 用量](/zh/guide/usage)。 |
| `/compact` | 立即总结对话，而不用等到窗口快满。 |
| `/self-compact` | 自我压缩：让模型在判断旧内容的细节已不再需要时，自己压缩自己的上下文。`/self-compact` 会打开一个面板：一条轨道管本会话，一条管所有会话的默认值；`on` / `off` / `default` 只设置当前会话，`global on` / `global off` 把默认值写进 `config.toml`。见[自我压缩](#self-compaction)。 |
| `/statusline` | 选择头部和状态行里哪些有名字的部分要显示——`ctx`、`cache`、`workspace` 等等。`/statusline` 打开面板（↑ ↓ 选部分，← → 隐藏或显示，`Enter` 应用）；`/statusline hide ctx speed`、`/statusline show all` 在键盘上做同样的事。保存在 `config.toml` 的 `[statusline]`。见[选择显示哪些部分](/zh/guide/interface#choosing-what-is-shown)。 |
| `/title` | 给会话命名：`/title users endpoint`；不带参数时报告当前名字。 |
| `/export` | 把这个会话导出成一个独立的 HTML 文件：`/export [path]`。 |
| `/quit`、`/exit` | 退出，并打印恢复这个会话的命令。 |

命令来自三个地方，菜单里也按这个顺序排列：外壳自己的（上面这些）、代理的（`/new`、`/compact`、
`/export`），以及任何[插件](/zh/guide/plugins)注册的。插件不能占用已存在的名字，所以 `/model`
永远是本页描述的行为。

## 继续被打断的请求 {#continue}

`/resume` 打开的是以前的*会话*；`/continue` 继续的是当前会话里*没做完的请求*。历史记录会说明它是怎么被打断的，
做什么取决于此：

| 怎么结束的 | `/continue` 做什么 |
| --- | --- |
| 模型回答之前就停了或失败了，或者工具已经跑完 | 再问一次模型，不添加任何内容。 |
| 工具运行时被停掉 | 告诉模型哪些工具被中断、可能执行过也可能没有，由它决定。**工具绝不会自己重新运行。** |
| provider 把回复截断了 | 告诉模型它被打断了，请从头重新写这段回复。 |
| 回复碰到输出上限 | 请模型从停下的地方接着写。 |
| provider 暂停了 | 把这一轮交还给 provider。 |
| 已经完成、被拒绝、或上下文窗口已满 | 什么都不做并说明原因：被拒绝的请求再发还会被拒绝；窗口满了需要 `/compact` 或 `/new`。 |

使用的是下一条消息会用的模型和推理强度，并且先说明它要做什么再去做。

## 自我压缩 {#self-compaction}

平时上下文是替你压缩的：达到模型的 `compact_percent` 时自动压缩，或者你输入 `/compact`。**自我压缩**增加了第三种方式：
模型会多得到一个 `compact_context` 工具，可以在判断某段已完成的工作不必再留在上下文里时（比如一个子任务做完之后），
自己把更早的对话总结掉。它不会压缩当前这一轮：本次请求连同其中的工具调用和结果原样保留；如果没有更早的轮次，
或总结并不比原文小，什么也不会发生。无论开不开，`/compact` 和自动阈值都照常工作。

默认关闭。有两处可以决定，更具体的一处优先：

| 是什么 | 怎么设置 | 作用范围 |
| --- | --- | --- |
| 默认值 | `config.toml` 里的 `[compaction] self = true`，或面板的第二条轨道，或 `/self-compact global on` / `off`（都会替你改这一行） | 所有没有自己选择过的会话 |
| 会话自己的选择 | 面板的第一条轨道，或 `/self-compact on` / `off` | 仅该会话；随会话保存，恢复或 fork 时延续 |
| 把选择还回去 | 面板里的 `default` 一档，或 `/self-compact default` | 该会话重新跟随默认值 |

所以把默认值打开，不会改变你已经选了 `off` 的会话；把它关掉，也不会改变选了 `on` 的会话。

### 面板

单独输入 `/self-compact` 会打开一个和 `/effort` 同风格的面板，有两条轨道：

```text
Self-compaction                                     in effect here: on (not applied)

▸ This session   ●━━━━━━━━━━━━━━━━━━━━━━━◉      default (off)    off     on
  Every session  ◉──────────────────────○      off              on
```

- **This session（本会话）：** `default`（没有自己的选择）、`off` 或 `on`。`default` 一档会说明它此刻等于什么，
  比如 `default (off)`，并随下面一条轨道的移动而变化。
- **Every session（全部会话）：** `off` 或 `on`，即配置里的默认值。
- ↑ ↓ 选择哪一行，← → 滑动旋钮，点击某一档会把旋钮送过去。按 `Enter` 之前什么都不会改变，`Enter` 会同时应用两条轨道；
  `Esc` 什么都不应用。旋钮离开起点时，标题右侧会显示将要生效的状态，并标注 `(not applied)`。
- 如果默认值写不进去（没有 `config.toml`），会告诉你，会话自己的选择仍然会应用。被别的进程占用的会话保持原样，
  只有下面那条轨道可以动。

开启时，状态行末尾会显示 `self-compact`。输入形式仍然可用：`/self-compact on|off|default` 和
`/self-compact global on|off`，带参数时会报告现在生效的是什么、依据是什么。`global` 需要已有的
`config.toml`：它不会替你创建文件，遇到无法安全编辑的文件会报告原因，而不是猜着改。

## 请求运行期间

大多数命令要等请求结束，因为它们会改动请求正依赖的东西。下面这些不用等：它们只查看会话，或者只改
请求并不依赖的设置，所以立刻运行，与请求并行。

| 立刻运行 | 为什么安全 |
| --- | --- |
| `/help`、`/plugins`、`/context`、`/usage`、`/theme` | 只是展示。`/context` 报告的是最近一次测量的请求；`/usage` 读的是已保存会话里记下的用量。 |
| `/bash` | 不读也不写会话；里面的命令是你自己的，所以后台运行的请求不受影响。 |
| `/title` | 给会话命名，运行中的请求不读它。 |
| `/permission` | 下一条 shell 命令会重新读取这个级别，所以修改会落在正在运行的请求里 —— 长任务进行到一半时 `/permission full` 正是为此。 |
| `/effort` | 请求以它开始时的 effort 运行，所以修改从下一个请求开始生效，正在运行的请求不受影响。 |
| `/self-compact` | 工具在请求开始时提供，所以修改从下一个请求开始生效；模型已经提出的申请，如果你随后关掉它就会被放弃。 |
| `/quit`、`/exit` | 离开不用等回答。 |
| `/btw` | 排队等轮到它再回答，和以前一样。 |
| `/code-review` | 同样排队：评审本身就是一次请求，等手上这次结束再开始。 |

`/model`、`/config`、`/clear`、`/new`、`/resume`、`/fork`、`/compact`、`/export` 仍然提示 “busy”：它们
会改变请求启动时用的模型、它正在写入的 transcript、或它所属的会话。[插件](/zh/guide/plugins#请求运行期间)
可以给自己的命令自行选择。

## Shell 面板 {#bash}

`/bash` 在工作区里打开一个全屏命令行，`/bash <命令>` 则打开后立即运行这条命令。它就是你自己的 shell、由你自己动手：
不需要权限确认，模型看不到其中任何内容，关闭面板后输出也随之消失。它不要求模型空闲，所以请求还在运行时也能打开。

```text
Shell (zsh)  ~/projects/api                              exit 0 · 1.2s
$ pytest -q
......
6 passed in 0.24s
────────────────────────────────────────────────────────────────
src/  tests/  README.md
$ git st_
enter run · tab complete · pgup scroll · esc close
```

| 按键 | 作用 |
| --- | --- |
| <kbd>Enter</kbd> | 运行命令。有命令在运行时，输入行保留你敲的内容，等它结束。 |
| <kbd>Tab</kbd> / <kbd>Shift</kbd>+<kbd>Tab</kbd> | 补全光标处的词；再按一次在候选里往后走，候选显示在输入行上方。 |
| <kbd>↑</kbd> <kbd>↓</kbd>、<kbd>Ctrl</kbd>+<kbd>R</kbd> | 翻阅、搜索以前的命令。 |
| <kbd>Ctrl</kbd>+<kbd>C</kbd> | 停止正在运行的命令（再按一次或等三秒会强制结束）。没有命令在运行时，关闭面板。 |
| <kbd>Esc</kbd> | 停止正在运行的命令；没有命令在运行时，关闭面板。 |
| <kbd>Ctrl</kbd>+<kbd>D</kbd> | 输入行为空时关闭面板，和结束一个 shell 一样。 |
| <kbd>Page Up</kbd> / <kbd>Page Down</kbd>、滚轮 | 滚动输出。在你向上滚之前它跟随最新一行；向上滚之后，新输出到来也不会把你正在看的内容挤走。 |
| `clear`、`exit` | 清空输出；关闭面板。 |

命令是怎么运行的：

- **每条命令一个进程**，在工作区里，用你自己的 shell 启动（`$SHELL -c`；Windows 上是 PowerShell，没有就用 `cmd`）。
  一条命令里设置的变量不会带到下一条，但单独的 `cd` 由面板自己处理并保留：下一条命令在上一条停下的目录里运行，标题里
  会显示当前目录。`cd x && make` 只在那一条命令里换目录。
- **没有输入。** 向程序提问时，它读到的是输入结束，并如实报告，而不是等一个谁也按不了的键。`vim`、`top` 这类接管整个屏幕的
  程序不适合在这个面板里用。
- **fish 不加载配置启动**（`fish --no-config -c`）。一般的配置下，加载 `config.fish` 每条命令要花半秒到一秒；`PATH` 和其余环境
  变量来自你启动 ZettCode 的那个 shell，所以缺的只是 `config.fish` 里定义的别名和函数。
- **颜色**按终端的方式请求：`ls`、`git`、`pytest`、`cargo` 以及所有读取 `FORCE_COLOR` 或 `CLICOLOR_FORCE` 的程序都会彩色输出，
  用回车刷新的进度条会原地更新。在环境里设置 `NO_COLOR` 可以关闭。Linux 上的 GNU `ls` 只有加 `--color` 才有颜色。

历史和补全：

- **历史**会读取 bash、zsh、fish 和 PowerShell 中你有的那些，`$SHELL` 对应的放在最后，所以它的命令在 <kbd>↑</kbd> 时排在最前。
  你在面板里敲的命令会追加到 `~/.zettcode/command_history`，下次还在。同一条命令只提供一次，放在它最新的位置。
- **Tab 补全**：第一个词补全成你以前运行过的命令，然后是 `PATH` 里的程序；后面的词补全成程序接受的内容（`git` 补全子命令，以及
  `checkout`、`merge`、`log` 等之后的分支、标签和远端），或者你上次运行同一命令时在那个位置敲过的词（`docker co` 找到 `compose`），
  以及当前目录里的文件。匹配不区分大小写，大小写完全一致的排在前面；`cd` 只给目录。
- **候选的颜色**像 `ls` 一样区分类型：目录、链接、可执行文件和分支各有自己的颜色，普通文件是最安静的那种。

## Token 用量 {#usage}

`/usage` 打开一个占满屏幕的页面，看这个项目的会话花了多少，分三个视图：按模型、按会话，以及一张按天的日历图。
`Tab` 在三个视图之间切换，`Esc` 关闭页面。

每个字段的含义、三个视图、数了什么没数什么，以及它和状态行的区别，都在 [Token 用量](/zh/guide/usage)。

## 短选择用菜单，其他用面板

`/permission`、`/theme` 是在几个固定的词里选一个，所以没有面板：单独输入它们时，输入框里会出现
命令加一个空格，菜单把各个词列出来，每个带一句说明，当前生效的那个标 `(current)` 并高亮。
`↑` / `↓` 移动，`Enter` 应用高亮的那一项。

`/effort` 有自己的面板：一条轨道，每个档位一个节点、一个名字，轨道上有一个小圆点。`←` / `→`（或 `Home` / `End`、鼠标点击）
让小圆点沿轨道滑过去，它经过的那一段会按档位的颜色亮起来（便宜的一端偏绿，贵的一端偏暖）。移动本身不改任何东西；
`Enter` 应用小圆点所在的档位，这时头部右上角原有的推理动画才开始播放。`Esc` 收起面板，档位保持原样。

`/model` 和 `/resume` 仍然打开选择列表：模型名可能带空格，会话最好连标题一起挑，这两点菜单里的一个词做不到。
`↑` / `↓` 移动，`Enter` 确认，
`Esc` 不做修改直接返回。`/context` 打开的是一页条形图报告，不需要选择，读完按 `Esc` 关闭即可；
报告里会写明这段对话写在 `~/.zettcode/sessions` 下的哪个文件，数字不对时能顺藤摸瓜。
总量是 provider 为上一次请求计费的数字，和状态行显示的是同一个数；本地统计只用来算比例，
所以每一行是该来源占总量的那一份，各行加起来正好等于总量；从磁盘恢复的会话没有对应的 provider 计数
（存档里的数字属于可能已被压缩掉的旧对话），这时各行就是本地统计的数。其中「环境说明」和「工具 schema」两行只存在于
运行时真正组装过的请求里，所以在某个会话的第一轮之前打开面板，这两行会显示为 `pending`，而不是被省略。
图片按估算计入，而不是按粘贴进来的体积——provider 是按尺寸和细节计费的。
面板下面的对话仍然可见。

切换模型、主题或推理档位会重新布局：头部和状态行读的就是面板写入的同一份状态，所以在你发下一条
消息之前，它们就已经显示新值了。

## 日常操作例子

下面这些命令都输入在 **ZettCode 输入框**中，不是在系统 shell 里执行。
需要参数时，先补全命令名，再输入空格和参数，最后按 `Enter` 执行。

| 想做什么 | 输入什么 | 会发生什么 |
| --- | --- | --- |
| 给当前任务起名 | `/title 修复登录超时` | 会话列表和状态行显示新标题。 |
| 换一个已配置的模型 | `/model DeepSeek Pro` | 后续请求使用这个模型，会话本身不变。 |
| 让困难的审阅多想一些 | `/effort high` | 修改后续请求的推理档位。 |
| 问一个不影响主任务的概念 | `/btw 这里的幂等是什么意思？` | 以只读旁路问题回答，不进入之后的上下文。 |
| 保存便于审阅的记录 | `/export review.html` | 在工作区中生成 HTML 导出。 |
| 继续之前的对话 | `/resume 01a10b75` | 从当前工作区的存储恢复对应会话。 |

这里的会话 id 只是示例，应换成自己的 `/resume` 列表里的 id。
模型名称必须对应配置中的模型；插件命令也要先安装插件才能使用。

### 开新会话、清屏和压缩有什么区别

| 命令 | 界面上的对话 | 下一次模型请求还记得什么 |
| --- | --- | --- |
| `/new` | 从空白开始 | 新会话，不带旧对话。 |
| `/clear` | 清空显示 | 当前会话的上下文仍然保留。 |
| `/compact` | 增加压缩结果 | 用摘要和近期上下文替代较早的细节。 |

这些命令都不会删除已保存的会话文件。无关的新任务用 `/new`，只想整理界面用 `/clear`，
想减小后续请求携带的内容用 `/compact`。单独切换模型不会重置上下文。

## `@` 资源

`@` 会把一个资源拉进消息里。提供资源的 provider 有两类：按路径引用的工作区文件，以及按名字引用的
[skills](/zh/guide/skills-and-mcp)。

> @zettcode/src/zettcode/cli.py 这个文件是做什么的？

输入 `@` 后菜单会同时列出两者，文件还会带着大小。文件引用发出去的是路径而不是内容：模型用自己的工具
去读，所以一次引用只占一句话的上下文，而不是一整个文件。目录会被标成目录，这样模型会去搜索而不是去读。
列出的范围是你大概会输入的那些，而不是磁盘上的一切：版本控制和依赖目录会被跳过，过大的仓库只列到上限。

存下来并显示给你的是你亲手打的草稿，所以之后恢复会话时看到的是 `@zettcode/src/zettcode/cli.py`
而不是展开后的一大段文字。skill 则是让它自己加载 —— 模型先看到名字，真正需要时才去读正文，这也是大目录
不会把每次请求都撑满的原因。

资源可以出现在消息的任何位置，一条消息里可以有多个；光标紧跟在芯片后面时，一次 **Backspace**
就能删掉整个芯片。

例如，安装 `code-review` 和 `test-plan` 两个 skill 后，可以这样输入：

```text
用 @code-review 审阅当前 diff，再用 @test-plan 建议还缺哪些测试。
```

两个引用都保留在句子对应的位置，前后的文字不会丢失。它们只是告诉模型要用哪个 skill，
而不是把整份正文放进每一个请求。安装步骤见[Skills 与 MCP](/zh/guide/skills-and-mcp)。
