# 命令

输入 `/` 就会打开菜单，边打边过滤，`Enter` 或 `Tab` 填入高亮的那一条。需要参数的命令在名字后
面加空格和参数 —— `/title users endpoint` —— 执行任何命令都不会离开当前界面。

有固定第一个词的命令，在输入命令名和空格之后会把它列出来：`/config ` 给出 `add`、`remove`、`list`、
`providers`，`/theme ` 给出各个配色，`/permission ` 给出它的档位，`/model ` 给出你配置过的
模型。`Tab` 填入其中一项，`Enter` 选中高亮的那一项并立即执行 —— `/model ` 再按 `↓` `Enter` 就直接切换模型，不再打开选择器。
`/config` 里需要继续输入的两个词（`add`、`remove`）只会被填入。

只有列表里的名字才是命令。其他以斜杠开头的内容 —— 比如路径 `/var/log/syslog`、打错的名字、`/tmp is full` —— 都是普通文本，
和其他消息一样发给模型。是命令的时候会立刻换成另一种颜色，所以你能看出它会按哪种方式处理。

| 命令 | 作用 |
| --- | --- |
| `/help` | 列出命令和快捷键。 |
| `/new` | 开一个新会话，旧会话仍留在磁盘上。 |
| `/clear` | 清空屏幕上可见的对话，会话本身继续。 |
| `/resume` | 弹出面板选择最近的会话；`/resume <id>` 直接打开指定会话。 |
| `/continue` | 从中断的地方继续一个没做完的请求 —— 被 `Esc` 停掉、失败、被 provider 断开、或碰到输出上限。见[继续](#continue)。 |
| `/fork` | 把当前对话带进一个新会话，并在那里继续。 |
| `/model` | 用面板选择后续请求使用的模型。 |
| `/config` | 不用改文件就能添加、修改、删除模型，并设置它是否接受图片、上下文窗口多大、什么时候压缩：`/config`、`/config add <provider> …`、`/config remove <序号>`。见[用 /config 添加模型](/zh/guide/config#adding-models-with-config)。 |
| `/effort` | 用轨道上的小圆点选择模型的推理强度：`/effort` 打开，← → 滑动，`Enter` 应用；`/effort high` 直接设置。 |
| `/permission` | 选择 shell 命令在多大范围内不用问：`/permission` 在菜单里列出各档，`/permission safe` 直接设置。 |
| `/btw` | 问一件只在当场回答、不进入对话的事：`/btw <问题>`。 |
| `/theme` | 按名字选配色：`/theme` 打开菜单，在菜单里移动时会预览每一套；`/theme nord` 一步切换。你自己的主题（`~/.zettcode/themes/<name>.toml`）也在菜单里。 |
| `/context` | 查看当前上下文窗口被什么占着，以及这个会话存在哪里。 |
| `/usage` | 打开一个页面，看这个项目的会话花了多少：按模型、按会话统计 token，以及一张按天的日历图。见[Token 用量](#usage)。 |
| `/compact` | 立即总结对话，而不用等到窗口快满。 |
| `/title` | 给会话命名：`/title users endpoint`；不带参数时报告当前名字。 |
| `/export` | 把这个会话导出成一个独立的 HTML 文件：`/export [path]`。 |
| `/quit`、`/exit` | 退出，并打印恢复这个会话的命令。 |

命令来自三个地方，菜单里也按这个顺序排列：外壳自己的（上面这些）、代理的（`/new`、`/compact`、
`/export`），以及任何[插件](/zh/guide/plugins)注册的。插件不能占用已存在的名字，所以 `/model`
永远是本页描述的行为。

## 继续被打断的请求 {#continue}

`/resume` 打开的是以前的*会话*；`/continue` 继续的是当前会话里*没做完的请求*。历史记录会说明它是怎么被打断的，
做什么取决于此：

| 怎么结束的 | `/continue` 做什么 |
| --- | --- |
| 模型回答之前就停了或失败了，或者工具已经跑完 | 再问一次模型，不添加任何内容。 |
| 工具运行时被停掉 | 告诉模型哪些工具被中断、可能执行过也可能没有，由它决定。**工具绝不会自己重新运行。** |
| provider 把回复截断了 | 告诉模型它被打断了，请从头重新写这段回复。 |
| 回复碰到输出上限 | 请模型从停下的地方接着写。 |
| provider 暂停了 | 把这一轮交还给 provider。 |
| 已经完成、被拒绝、或上下文窗口已满 | 什么都不做并说明原因：被拒绝的请求再发还会被拒绝；窗口满了需要 `/compact` 或 `/new`。 |

使用的是下一条消息会用的模型和推理强度，并且先说明它要做什么再去做。

## 请求运行期间

大多数命令要等请求结束，因为它们会改动请求正依赖的东西。下面这些不用等：它们只查看会话，或者只改
请求并不依赖的设置，所以立刻运行，与请求并行。

| 立刻运行 | 为什么安全 |
| --- | --- |
| `/help`、`/context`、`/usage`、`/theme` | 只是展示。`/context` 报告的是最近一次测量的请求；`/usage` 读的是已保存会话里记下的用量。 |
| `/title` | 给会话命名，运行中的请求不读它。 |
| `/permission` | 下一条 shell 命令会重新读取这个级别，所以修改会落在正在运行的请求里 —— 长任务进行到一半时 `/permission auto` 正是为此。 |
| `/effort` | 请求以它开始时的 effort 运行，所以修改从下一个请求开始生效，正在运行的请求不受影响。 |
| `/quit`、`/exit` | 离开不用等回答。 |
| `/btw` | 排队等轮到它再回答，和以前一样。 |

`/model`、`/config`、`/clear`、`/new`、`/resume`、`/fork`、`/compact`、`/export` 仍然提示 “busy”：它们
会改变请求启动时用的模型、它正在写入的 transcript、或它所属的会话。[插件](/zh/guide/plugins#请求运行期间)
可以给自己的命令自行选择。

## Token 用量 {#usage}

`/usage` 会打开一个全屏页面，显示当前项目的会话一共花了多少。数字是从已保存的对话里读回来的，
所以统计的是项目里的**所有**会话，而不只是当前这一个，一小时后再看也是同样的结果。页面有三个
视图，用 `Tab`（或 `1`、`2`、`3`）切换：

- **Models**：每个模型一组输入、输出两根条形图，旁边写着输入里有多少来自服务商缓存、输出里有多少是推理。
  输入和输出各用各的比例尺，因为对每个模型来说输出都只是输入的一小部分。
- **Sessions**：每个会话一行，按最后一次修改时间排序，写着开始时间、最后修改时间、标题、输入和输出的
  条形图，以及这次输入里有多少来自服务商缓存（同样用条形图表示）。token 条形图用平方根比例，这样小会话在特别大的会话旁边也看得见；缓存条形图则是标准的
  0–100%（满格表示输入全部命中缓存），所以行与行之间可以直接比较。终端变窄时先去掉条形图，再去掉缓存列，再去掉时钟，最窄的时候
  只保留最后修改时间——排序依据的就是它。页面上所有的缓存命中率都保留两位小数。
- **Calendar**：像 GitHub 贡献图一样的周历：一列是一周，一格是一天，颜色深浅是当天的 token
  （输入加输出），从没用到用量最重的那四分之一天。`←` `→` 按周移动，`↑` `↓` 按天移动，网格下面一行写着
  选中那天花了多少，以及连续使用的天数。终端越宽显示的周数越多，最多一年。

`↑` `↓`、`PgUp`、`PgDn`、`Home`、`End` 和鼠标滚轮可以滚动长列表；`Esc` 或 `q` 关闭页面。
统计口径有三点：

- 一条回复只算一次。`/fork` 会把对话连同每条回复的用量一起复制到新会话，所以分叉出来的会话只显示
  它分叉之后自己花的；之前的回复仍算在最早写下它们的那个会话里。
- 子智能体自己的会话不计入：那不是你进行的对话。
- 一天按你所在时区算，所以晚上十一点半写下的回复算在你看到它的那一天。

旧版本保存的会话也会被统计，前提是其中的回复带着用量；没有用量的回复不会被估一个数字，而是不计。

历史很长的项目里，第一次 `/usage` 需要读完所有对话，几 GB 的数据可能要几秒。之后 ZettCode 会在该项目的会话目录
（`~/.zettcode/sessions` 下）旁边留一个很小的 `usage.json`，往后的每一次 `/usage`（无论是这次运行还是下次运行）只读新增的部分。
这个文件只是一个捷径：随时可以删除，ZettCode 下次会自动重建。

## 短选择用菜单，其他用面板

`/permission`、`/theme` 是在几个固定的词里选一个，所以没有面板：单独输入它们时，输入框里会出现
命令加一个空格，菜单把各个词列出来，每个带一句说明，当前生效的那个标 `(current)` 并高亮。
`↑` / `↓` 移动，`Enter` 应用高亮的那一项。

`/effort` 有自己的面板：一条轨道，每个档位一个节点、一个名字，轨道上有一个小圆点。`←` / `→`（或 `Home` / `End`、鼠标点击）
让小圆点沿轨道滑过去，它经过的那一段会按档位的颜色亮起来（便宜的一端偏绿，贵的一端偏暖）。移动本身不改任何东西；
`Enter` 应用小圆点所在的档位，这时头部右上角原有的推理动画才开始播放。`Esc` 收起面板，档位保持原样。

`/model` 和 `/resume` 仍然打开选择列表：模型名可能带空格，会话最好连标题一起挑，这两点菜单里的一个词做不到。
`↑` / `↓` 移动，`Enter` 确认，
`Esc` 不做修改直接返回。`/context` 打开的是报告，不需要选择，读完按 `Esc` 关闭即可；
报告里会写明这段对话写在 `~/.zettcode/sessions` 下的哪个文件，数字不对时能顺藤摸瓜。
标题里的总量是 provider 为上一次请求计费的数字，各行百分比则是本地测出来的——所以百分比加起来是
100%，而总量和状态行显示的是同一个数；从磁盘恢复的会话没有对应的 provider 计数（存档里的数字属于
可能已被压缩掉的旧对话），这时两者都以本地测量为准。其中「环境说明」和「工具 schema」两行只存在于
运行时真正组装过的请求里，所以在某个会话的第一轮之前打开面板，这两行会显示为 `pending`，而不是被省略。
图片按估算计入，而不是按粘贴进来的体积——provider 是按尺寸和细节计费的。
面板下面的对话仍然可见。

切换模型、主题或推理档位会重新布局：头部和状态行读的就是面板写入的同一份状态，所以在你发下一条
消息之前，它们就已经显示新值了。

## 日常操作例子

下面这些命令都输入在 **ZettCode 输入框**中，不是在系统 shell 里执行。
需要参数时，先补全命令名，再输入空格和参数，最后按 `Enter` 执行。

| 想做什么 | 输入什么 | 会发生什么 |
| --- | --- | --- |
| 给当前任务起名 | `/title 修复登录超时` | 会话列表和状态行显示新标题。 |
| 换一个已配置的模型 | `/model DeepSeek Pro` | 后续请求使用这个模型，会话本身不变。 |
| 让困难的审阅多想一些 | `/effort high` | 修改后续请求的推理档位。 |
| 问一个不影响主任务的概念 | `/btw 这里的幂等是什么意思？` | 以只读旁路问题回答，不进入之后的上下文。 |
| 保存便于审阅的记录 | `/export review.html` | 在工作区中生成 HTML 导出。 |
| 继续之前的对话 | `/resume 01a10b75` | 从当前工作区的存储恢复对应会话。 |

这里的会话 id 只是示例，应换成自己的 `/resume` 列表里的 id。
模型名称必须对应配置中的模型；插件命令也要先安装插件才能使用。

### 开新会话、清屏和压缩有什么区别

| 命令 | 界面上的对话 | 下一次模型请求还记得什么 |
| --- | --- | --- |
| `/new` | 从空白开始 | 新会话，不带旧对话。 |
| `/clear` | 清空显示 | 当前会话的上下文仍然保留。 |
| `/compact` | 增加压缩结果 | 用摘要和近期上下文替代较早的细节。 |

这些命令都不会删除已保存的会话文件。无关的新任务用 `/new`，只想整理界面用 `/clear`，
想减小后续请求携带的内容用 `/compact`。单独切换模型不会重置上下文。

## `@` 资源

`@` 会把一个资源拉进消息里。提供资源的 provider 有两类：按路径引用的工作区文件，以及按名字引用的
[skills](/zh/guide/skills-and-mcp)。

> @src/zettcode/cli.py 这个文件是做什么的？

输入 `@` 后菜单会同时列出两者，文件还会带着大小。文件引用发出去的是路径而不是内容：模型用自己的工具
去读，所以一次引用只占一句话的上下文，而不是一整个文件。目录会被标成目录，这样模型会去搜索而不是去读。
列出的范围是你大概会输入的那些，而不是磁盘上的一切：版本控制和依赖目录会被跳过，过大的仓库只列到上限。

存下来并显示给你的是你亲手打的草稿，所以之后恢复会话时看到的是 `@src/zettcode/cli.py`
而不是展开后的一大段文字。skill 则是让它自己加载 —— 模型先看到名字，真正需要时才去读正文，这也是大目录
不会把每次请求都撑满的原因。

资源可以出现在消息的任何位置，一条消息里可以有多个；光标紧跟在芯片后面时，一次 **Backspace**
就能删掉整个芯片。

例如，安装 `code-review` 和 `test-plan` 两个 skill 后，可以这样输入：

```text
用 @code-review 审阅当前 diff，再用 @test-plan 建议还缺哪些测试。
```

两个引用都保留在句子对应的位置，前后的文字不会丢失。它们只是告诉模型要用哪个 skill，
而不是把整份正文放进每一个请求。安装步骤见[Skills 与 MCP](/zh/guide/skills-and-mcp)。
